## Bug 修复：平台商店种子数据在老用户上不显示

**问题**：`autoSeed()` 只检查 `wallet_v2` + `allinone_published_games`，已有老数据的用户不会触发 `seedPlatformGameStores()`，导致原神等测试数据不显示。

**修复**：
- `autoSeed()` 新增 `platform_game_stores` 检测，缺失时自动调用 `seedPlatformGameStores()` 增量补填
- `__seedDiag()` 诊断列表加入 `platform_game_stores` key
- 老用户无需清空 localStorage，刷新页面即可自动补填平台商店数据

## 后端兑换码 API + 开发者指南 实施

按用户需求完成两部分：

### 一、后端 API 接入
1. **新建** `src/server/redeemCodeStore.ts` - 服务端兑换码存储（内存模式 + 可扩展 PostgreSQL）
   - 支持 `syncCodes` / `syncItems` 从前端同步数据
   - 支持 `verifyCode` / `useCode` 业务方法
2. **修改** `server.js` - 新增 4 个 API 端点：
   - `POST /api/redeem/sync` - 前端同步兑换码到后端
   - `POST /api/redeem/verify` - 游戏方验证兑换码（幂等，不修改状态）
   - `POST /api/redeem/use` - 游戏方核销兑换码（标记已用+发放道具）
   - `GET /api/redeem/stats` - 统计信息（调试用）
   - 启动日志加入兑换码统计
3. **修改** `src/services/redeemCodeService.ts` - 新增后端同步与 API 客户端方法：
   - `setApiBaseUrl()` / `getApiBaseUrl()` - 配置后端地址
   - `syncToBackend()` - 同步 localStorage 数据到后端（generateCodes/purchaseCodes/useCode 后自动调用）
   - `verifyCodeViaApi()` - 通过后端 API 验证（失败回退本地）
   - `useCodeViaApi()` - 通过后端 API 核销（失败回退本地）
4. **修改** `cloudfunctions/db_init/init.cjs` - 新增 `redeem_codes` + `game_stores` 集合定义及安全规则
