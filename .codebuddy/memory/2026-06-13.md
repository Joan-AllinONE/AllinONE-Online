# 2026-06-13 工作日志

## 修复：发布游戏后无法正常运行（第二轮 — 根因修复）

### 根本原因
**服务器返回 base64 编码的字符串而非实际 HTML/JS/CSS 内容**。

问题链路：
1. ZIP 解压时所有文件都用 `uint8array` 读取（`zipEntry.async('uint8array')`）
2. PublishingPipeline 上传时，`Uint8Array` 全部用 `btoa()` 转为 base64（不区分文本/二进制）
3. 服务器原样存储 base64 字符串
4. 服务时 `isBase64Encoded()` 对含 `charset` 的 MIME 返回 false，直接 `res.send(base64字符串)`
5. 浏览器收到 base64 乱码而非实际 HTML → 游戏白屏

### 修改文件

1. **src/publishing-center/core/PublishingPipeline.ts**（核心修复）
   - 新增 `TEXT_EXTENSIONS` 集合判断文本/二进制文件
   - 文本文件：`Uint8Array` → `TextDecoder('utf-8').decode()` → UTF-8 字符串
   - 二进制文件：`Uint8Array` → `btoa()` → base64（仅二进制文件用 base64）

2. **src/server/routes/games.ts**（服务端兼容修复）
   - 新增 `isTextMimeType()` 和 `looksLikeBase64()` 函数
   - 服务文件时自动检测文本 MIME + base64 内容 → 解码后返回 UTF-8
   - 兼容旧版上传的 base64 编码文本文件

3. **src/services/publishedGameService.ts**（本地存储解码修复）
   - `getGameEntryContent()` 和 `getSelfContainedGameHtml()` 中使用 `decodeFileContent()`
   - 新增 `decodeFileContent()`：解码 `__BINARY_BASE64__` 前缀（TextDecoder UTF-8）

4. **src/pages/GamePlay.tsx**（重新上传修复）
   - `reuploadGameFiles()` 中文本文件解码 `__BINARY_BASE64__` 前缀（TextDecoder UTF-8）
   - 二进制文件保留前缀让服务器处理
