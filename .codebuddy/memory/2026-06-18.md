## localStorage 配额溢出 → 游戏发布失败修复

### 背景
用户测试游戏发布时报错：`Failed to execute 'setItem' on 'Storage': Setting the value of 'allinone_published_games' exceeded the quota.`
根因：25+游戏元数据（含 RedeemItemConfig/GameItemSop/skillConfigs 等大字段）+凭证+交易+CloudBase凭证+写入队列等，总计超出浏览器 localStorage ~5MB 上限。

CloudBase Auth 凭证也出现类似报错（但最终成功）。

### 修改文件

1. **src/services/publishedGameService.ts** — 核心修复
   - 新增 `saveGamesToStorage()` 函数：localStorage → 尝试释放空间 → 重试 → 降级 IndexedDB
   - 新增 `freeLocalStorageSpace()` 函数：清除旧格式游戏文件数据（已在 IndexedDB 中的大块数据）
   - 新增 `loadGamesFromIDB()` 函数：从 IndexedDB 加载游戏元数据并回写 localStorage
   - 所有 `localStorage.setItem(STORAGE_KEY, ...)` 替换为 `saveGamesToStorage()`
   - `getPublishedGames()` 新增 IndexedDB 异步回退加载 + `games-list-updated` 事件
   - `savePublishedGame()` 改为 async：缓存空时先等待 IndexedDB 加载，防止丢失已有游戏
   - `saveGamesToStorage()` IndexedDB 保存前先合并已有数据，防止覆盖丢失
   - `clearPublishedGames()` 同时清理 IndexedDB
   - 新增 `_idbLoadInitiated` 标志防止重复加载

2. **src/publishing-center/core/PublishingPipeline.ts** — `savePublishedGame` 调用加 `await`

3. **src/pages/PublishingCenter.tsx** — `handlePublishComplete` 改 async + `await savePublishedGame`

### 存储架构变化
- **之前**：游戏元数据仅存 localStorage，配额不足时崩溃
- **之后**：localStorage → 尝试释放空间 → IndexedDB 自动降级，零数据丢失

## 上线前全量数据存储审计 + 修复（8个文件）

### 背景
用户要求：平台准备上线，必须确保数据存储以后端数据库为首要方式，不能依赖 localStorage/IndexedDB，否则会出现数据丢失、不同步、报错等问题。

### 发现的系统性问题
1. **cloudSync.ts 合并策略缺陷**：`loadWithCloudSync` 仅"补充"本地缺失 ID，不"覆盖"本地旧数据。这意味着 CloudBase 的权威数据无法修正本地错误数据
2. **redeemCodeService.ts 数据截断**：`syncToCloudBase` 只同步最近20条(`items.slice(-20)`)，大量历史数据可能丢失
3. **多个服务读取路径问题**：先读 localStorage 返回，CloudBase 仅异步"补充"缺失 ID，而非覆盖旧数据
4. **thresholds/penaltyLogs 无 CloudBase 同步**：投票门槛和惩罚日志完全依赖 localStorage
5. **ExtensionVoucher 纯 localStorage**：扩展凭证无任何 CloudBase 同步

### 修复的文件（8个）

| 文件 | 修复内容 |

| ExtensionVoucher.ts | save() 新增 writeQueue.enqueue 写入 `extension_vouchers` 集合；新增 refreshFromCloud() 方法 |

## CloudBase Auth localStorage 配额保护 + WriteQueue auth 断裂检测

### 背景
上传测试游戏后控制台出现大量报错（100+ WriteQueue "Gave up after 5 retries" 日志洗屏）。
根因链：localStorage 满 → CloudBase 匿名登录 credentials 无法 setItem → auth scope 为 null → 所有 DB 操作报 "Cannot read properties of null (reading 'scope')" → WriteQueue 每条记录独立重试5次 → 100+ 条 × 5 次重试 = 控制台洗屏。

### Fix 1: cloudbase.ts — Auth 登录前清理 localStorage 空间
- 新增 `ensureLocalStorageSpaceForAuth()` 函数：匿名登录前清除可重建的缓存数据（`allinone_game_files_*`、`allinone_published_games`、`allinone_write_queue`），腾出空间给 credentials 写入
- `initCloudBase()` 中在 `signInAnonymously()` 前调用清理
- 如仍因 quota 失败，二次清理后重试一次

### Fix 2: writeQueue.ts — Auth 断裂检测 + 失败汇总
- 新增 `AUTH_ERROR_PATTERN` 正则（匹配 scope null / INVALID_CREDENTIALS）
- 新增 `authBroken` 标志 + `auth_paused` 状态：检测到 auth 错误时立即暂停处理器，将所有受影响条目标记为 `auth_paused`
- 新增 `checkAuthRecovery()`：每 10 秒轻量检查 auth 是否恢复（读 `__healthcheck__` 集合），恢复后自动重启处理
- 新增 `failureSummary` + `flushFailureSummary()`：失败日志按 collection+operation 汇总输出（而非逐条 console.error 洗屏）
- `retryAll()` 支持重试 `auth_paused` 项并重置 `authBroken`
- `QueueStatus` 新增 `authPaused` + `authBroken` 字段

- 2个修改文件 0 lint 错误
- pnpm build: exitCode 0 成功

## COS 云存储上传 0B 修复 + CORS 配置

### 背景
用户测试游戏发布时，COS Bucket CORS 缺失导致浏览器拦截跨域 PUT 请求，云存储上传失败。CORS 配置后上传成功但文件为 0B（空文件）。

### 根因分析
1. **COS CORS 缺失**（已通过控制台配置解决）：CloudBase JS SDK v2 `uploadFile()` 直接向 COS 发 PUT 请求，Bucket 无 CORS 规则则浏览器拦截 preflight
2. **0B 文件**：代码用 `new Blob([content], {type: 'application/octet-stream'})` 创建 Blob，传 `fileContent: blob`。CloudBase Web SDK v2 期望 `filePath` 传 File 对象（有 name 属性），裸 Blob 无 name 属性导致 SDK 无法正确获取文件大小和内容，文件元数据创建成功但内容体为空

### 修复：src/services/cloudbaseStorage.ts
- `new Blob(...)` → `new File([content], fileName, {type: contentType})`：File 对象有 name 属性，SDK 能正确传输
- `fileContent: blob` → 同时传 `filePath: fileObj` + `fileContent: fileObj`：兼容 v2/v1 不同参数名
- `application/octet-stream` → `inferContentType(fileName)`：HTML 用 text/html，CSS 用 text/css 等，帮助 COS 正确存储
- 新增上传前空文件检测（fileObj.size === 0 时跳过并记录）
- 新增上传结果验证（检查 fileID 和打印详细日志）

### 其他控制台报错说明
- **game-developers 404**：Express 后端未启动，Vite proxy 到 localhost:3000 但连接失败。游戏商账户降级为内存+CloudBase Auth 模式
- **AI hunyuan-exp 403**：CloudBase AI 模型 `hunyuan-exp` 组未开通/授权，GameCodeAnalyzer 自动降级为本地检测

- pnpm build: exitCode 0
- 0 lint error
