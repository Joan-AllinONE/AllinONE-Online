## place_mine + infinite_ore 缺陷修复（06-23 第二轮）

### place_mine 修复 — 世界坐标存储
**根因**：地雷存储的是放置时的屏幕坐标 `(sx,sy)`，但敌方位置是实时扫描转换的屏幕坐标。游戏镜头移动后两套坐标系错位，地雷永不引爆。

**修复**：
1. 新增 `screenToWorld(sx,sy)` — 屏幕→世界坐标逆映射
2. 新增 `worldToScreen(cellX,cellY)` — 世界→屏幕坐标（含当前镜头偏移）
3. `_placeMine` 同时存储 `cellX/cellY`（世界坐标）和 `sx/sy`（初始显示位置）
4. 检测循环中每轮调用 `worldToScreen(mine.cellX, mine.cellY)` 获取实时屏幕坐标
5. `detonateMine` 爆炸位置也用 `worldToScreen` 计算

### infinite_ore 修复 — localStorage 主路径 + DOM 辅助
**根因**：完全依赖 `#mv-credits` DOM 元素存在，游戏未加载时静默失效；第二个 setInterval 未保存 ID 导致内存泄漏；onGameTick 直接覆盖式赋值。

**修复**：
1. **主路径**：`localStorage.setItem('ra2.cash')` 每秒写入（与 add_cash 同机制，可靠性高）
2. **DOM 辅助**：`_oreFloatInterval` 保存 ID，尝试注入 `#mv-credits` 但不阻塞
3. **内存泄漏**：新增 `_oreFloatInterval` 变量，deactivate 时清理
4. **onGameTick 引用**：`_oreGameTick` 保存引用，deactivate 时做等值判断再清除
5. **游戏实例同步**：同步 `_ra2.playerCash`（如存在）
6. `activateInfiniteOre` 开头加 `if (_oreActive) deactivateInfiniteOre()` 防重复激活

## Bug 修复（06-23 第三轮）— 全面审查修复

### Bug 1: `place_mine` 缺少 `_minePlacing` 防护
**后果**：连续点击两次道具 → 两组事件监听器，双倍地雷放置 + 幽灵元素泄漏
**修复**：handler 入口添加 `if (_minePlacing) return { message: '⚠️ ...' };` 守卫
同时添加 params 约束校验（damage 30-150, radius 1-4, triggerPx 30-100）

### Bug 2: 全部 `localStorage.getItem('ra2.cash')` 读取缺少 NaN 保护
**后果**：一旦 localStorage 被污染（如手动输入非数字值），`Number('abc')` = `NaN`，`NaN + 1000` = `NaN`，String(NaN) = `"NaN"` → 资金永久损坏
**修复**：`add_cash`、`infinite_ore`、`airdrop_supply` 三处改为安全读取：
`var raw = localStorage.getItem('ra2.cash'); var cur = (raw && !isNaN(Number(raw))) ? Number(raw) : 5000;`
`airdrop_supply` 和 `add_cash` 的 `_ra2.playerCash` 赋值前加 `typeof === 'number'` 检查

### Bug 3: `doAirdropVisual` 着陆闪光错位
**后果**：箱子动画终点 `100vh - 140px`，但闪光在 `100vh - 160px`，错位 20px
**修复**：统一为 `100vh - 140px`

### Bug 4: 5 个效果双 Toast（去重）
**后果**：`reveal_map`、`speed_boost`、`armor_boost`、`power_surge`、`place_mine` 在 activate 函数内部调用 `showToast()`，同时 `useCustomPowerUp()` 也会根据 handler return 再显示一次 → 每次使用弹两条提示
**修复**：移除 activate 函数内部的 `showToast` 调用（共 7 处），统一由 `useCustomPowerUp` 根据 handler return 的 `{message}` 驱动
保留独立事件触发的 toast（`detonateMine` 爆炸通知、`_placeMine` onClick 部署通知）

### Bug 5: 激活函数内 `deactivateXxx` 的结束 toast 也被移除
与Bug4同步修复，避免激活/结束时都弹多余toast。耗时效果通过徽章倒计时直观展示状态变化。

## reveal_map 调试与健壮性修复（06-23 第四轮）

### 根因分析
用户反馈 `reveal_map` 无效果。日志显示 SDK Effect Engine 将其归类为 `custom`（no-op），实际 `activateRevealMap` 未被调用。根本原因：
1. **无调试日志**：`activateRevealMap`/`scanAndDrawReveal` 多处静默 `return`，用户无法判断哪一步失败
2. **小地图未就绪**：道具使用时机可能早于游戏渲染 `#mv-mini`
3. **z-index 不够高**：`9996` 可能被游戏主 canvas 遮挡
4. **无视觉确认**：即使扫描成功，小圆点不明显；扫描失败也无提示

### 修复内容

1. **`ensureRevealOverlay`** — z-index 提升到 `2147483647`（最大安全值），日志输出 canvas 尺寸
2. **`scanAndDrawReveal`** — 返回值 `true/false`；每处 `return` 前加 `console.warn` 日志；首次成功输出己方/敌方单位统计；图例含实时计数；像素点加大变亮（r=6/4, opacity 0.95/0.8）
3. **`activateRevealMap`** — 首次扫描失败后启动**重试机制**（每 300ms 重试，最多 20 次/6 秒）；超时后在画布中央显示"⚠️ 小地图数据未就绪"降级提示；添加 `console.log` 状态追踪
4. **`reveal_map` handler** — 添加**瞬时蓝色闪光**（`rgba(68,170,255,0.15)` + 0.5s fade-out），确保用户立即看到视觉反馈
5. **`deactivateRevealMap`** — 重置调试标记，输出停用日志

## 道具实际游戏状态修改（06-23 第六轮）— 三层注入突破引擎封闭

### 核心发现
通过分析 `gd` 类（UI控制器，行1251+）的完整结构，发现游戏实例 `h = new gd(...)` 虽是局部变量，但：
- `class gd` 定义在全局作用域（非 IIFE），AllinONE IIFE 中可访问
- `gd.prototype.init` 可猴子补丁以捕获 `this`（即游戏实例）
- `gd.prototype.stepWith` 可猴子补丁以注入每tick后处理

### 三层注入架构
**Layer 1: 游戏实例捕获** — `gd.prototype.init` 猴子补丁
→ 存储 `_ra2._gameInstance = this`（含 `world.entities`, `world.players`, `world.rules.units` 等完整接口）

**Layer 2: 每tick注入** — `gd.prototype.stepWith` 猴子补丁
→ 在 `world.step()` + `onAfterStep()` 执行完毕后注入：
  - `_injectPowerSurge(this)` — 重置 `player.powerDrained = 0`
  - `_injectArmorHealBack(this)` — HP快照对比 + 损伤回补

**Layer 3: 效果处理器改造**

### 具体改造内容

**1. repair_all — 实际HP修复**
- 遍历 `world.entities.values()` 筛选 `owner === localPlayerId`
- `entity.hp = rules.hp`（恢复至 maxHP）
- 输出修复计数日志
- 保留3次绿色脉冲闪屏 + localStorage 备用信号

**2. power_surge — 实际无限电力**
- 新增 `_injectPowerSurge(game)` — 每tick设置 `player.powerDrained = 0`
- 强制 HUD：`game.powerEl.textContent = powerProduced + '/0'`
- 停用时下一tick自然恢复真实电力显示
- 保留闪电视觉 + 倒计时徽章

**3. armor_boost — 实际伤害减免（HP回补机制）**
- 新增 `_armorMultiplier` + `_armorPrevHp`（entity.id → 上次HP快照）
- `_snapshotPlayerHp(game)` — 激活时快照全部玩家非建筑单位HP
- `_injectArmorHealBack(game)` — 每tick：
  - 对比 `_armorPrevHp` vs 当前 `entity.hp` 计算损伤量
  - 回补 `hpLoss * (1 - 1/multiplier)`（multiplier=2 → 回补50%, multiplier=3 → 回补67%）
  - 不超过 `rules.hp`（maxHP）
  - 新单位自动注册，死亡单位自动清理
- 保留护盾扫描线 + 徽章视觉

### 边界处理
- 游戏未启动（无 `_gameInstance`）→ 优雅降级，仅视觉 + localStorage
- `gd` 不可全局访问 → console.warn + MutationObserver 后备
- 新单位/死亡单位 → armor_boost 自动处理
- `pnpm build` 通过 ✅
