## 修复：发布游戏对多用户可见性问题

**问题**：CloudBase 安全规则已设为 `read: true`，但用户 A 上传游戏后用户 B 仍无法在游戏中心看到。

**根因**（4个连锁问题）：
1. `_cloudSyncInitiated` 标志位在首次 CloudBase 刷新开始时就锁定，失败后永不重试
2. `GameCenter.tsx` 只监听 `storage` 事件（跨标签页），未监听 `games-list-updated`（同页面 JS 触发）
3. `loadGamesFromCloudBase()` catch 块静默吞错返回 `[]`，上层无法感知失败
4. `refreshGamesFromCloudBase()` 空结果时不更新缓存、不派发事件

**修改文件**：
- `src/services/publishedGameService.ts`：
  - 移除 `_cloudSyncInitiated`，替换为 `_cloudRefreshRetries` 重试计数器（最大3次，指数退避 1s/2s/4s）
  - 新增 `scheduleCloudRefresh()` 带重试的调度器
  - `loadGamesFromCloudBase()` 移除 try-catch 静默吞错，让异常上抛
  - `refreshGamesFromCloudBase()` 返回 `Promise<number>`，无论空/非空都更新缓存+派发事件
- `src/pages/GameCenter.tsx`：useEffect 新增 `games-list-updated` 事件监听

**验证**：0 lint 错误，tsc 无新增错误（仅有预存未使用变量警告）

## 修复：WriteQueue 批量失败 + VoucherDatabase 全量同步洪水 (2026-07-01 第三轮)

**问题**：控制台显示 writeQueue 228 条失败（累计 456 次），全部是 `vouchers upsert` / `voucher_transactions upsert` / `redeem_hosted_items upsert`，错误为 `Cannot read properties of undefined (reading 'length')`。

**根因**（2 个连锁问题）：

1. **`writeQueue.ts` upsert 处理器缺少空值保护**：
   - `res.data.length` 在 CloudBase SDK 返回异常（如集合不存在）时崩溃
   - `res.data` 为 `undefined` 时 `.length` 抛出 TypeError
   - 失败后进入指数退避重试 → 5 次后永久标记 failed → 队列堆积

2. **`VoucherDatabase` 全量同步导致队列洪水**：
   - 每次修改任何凭证 → `syncVouchersToCloud()` 全量遍历缓存所有凭证入队
   - 如果缓存有 146 张凭证 + 交易记录 → 每次变更产生数百条 upsert
   - 其中任何一条失败都会蔓延，导致诊断面板显示 44 成功 vs 228 失败

**代码修复**：

| 文件 | 修改 |
|------|------|
| `writeQueue.ts` | upsert 两个分支：`res.data.length` → `res?.data?.length`；新增 try-catch 处理集合不存在的场景（fallback 到 add） |
| `VoucherDatabase.ts` | 全量同步 → 增量同步：新增 `cloudSyncDirtyVouchers/Transactions` 集合追踪变更条目；`insertVoucher/updateVoucher/insertTransaction` 标记脏条目；`syncVouchersToCloud/syncTransactionsToCloud` 仅入队脏条目；新增 `scheduleCloudSyncFallback()` 作为 2s 防抖全量兜底 |

**验证**：0 lint 错误，tsc 零新增类型错误

## 修复：跨浏览器游戏文件加载失败 (2026-07-01 第四轮)

**问题**：用户 B（不同浏览器）能看到游戏列表，但游戏无法运行。
控制台报错：
- `TypeError: o.listFiles is not a function` — `loadGameFilesFromCloud()` 使用了不存在的 API
- `Failed to launch 'local://...'` — `cdnUrl` 被设为无效 `local://` 协议 URL

**根因**（3 个连锁问题）：

1. **`loadGameFilesFromCloud()` 调用不存在的 `app.listFiles()`**
   - CloudBase JS SDK (浏览器端) 没有 `listFiles` 方法（那是 Node SDK 的）
   - 导致云存储文件下载完全不可用

2. **跨浏览器无游戏文件来源**
   - localStorage/IndexedDB 仅在本浏览器有效
   - 云存储下载因 #1 崩溃
   - 最终 fallback 到 `cdnUrl`

3. **`cdnUrl` 在 inline 模式被设为 `local://game/xxx`**
   - `PublishingPipeline.ts` 第 735 行：`cdnUrl: "local://game/{gameId}/{entryPoint}"`
   - 浏览器无法识别 `local://` 协议 → iframe 空白

**代码修复（修改 3 个文件）**：

| 文件 | 修改 |
|------|------|
| `cloudbaseStorage.ts` | `uploadGameFiles` 新增返回 `fileManifest`（cloudFileID 清单） |
| `publishedGameService.ts` | (1) `saveGameFiles`: 上传后存储 `cloudFileManifest` + `entryHtmlContent` 到文档；(2) `loadGameFiles`: 新增步骤④「从文档读取 entryHtmlContent」— 跨浏览器最快路径；(3) 完全重写 `loadGameFilesFromCloud`: 先读 `cloudFileManifest` 用 `getTempFileURL` 下载，失败回退到路径推测；(4) 新增 `loadEntryHtmlFromDocument` / `downloadFilesFromManifest` / `downloadFilesFromPathGuess` |
| `PublishingPipeline.ts` | inline 模式不再设置 `cdnUrl` 为 `local://`，改为 `undefined` |

**跨浏览器加载链路（修复后）**：
```
浏览器 B 访问 /game/:gameId
  → loadGameFiles()
  → ① localStorage: 空（不同浏览器）
  → ② 旧格式分块: 空
  → ③ IndexedDB: 空
  → ④ entryHtmlContent（从 CloudBase 文档读取）✨ 返回 HTML 内容
  → getSelfContainedGameHtml() 拿到内容 → iframe srcDoc 渲染 ✅
```

**验证**：0 lint 错误，tsc 零新增类型错误
