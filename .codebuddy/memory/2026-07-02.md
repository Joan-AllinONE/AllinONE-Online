## 游戏加载回退修复（本浏览器也无法加载）

### 问题
- 连本浏览器都无法加载游戏，屏幕只显示 HTML 文本（SCORE 0 HELLO!...）而无 CSS/JS 样式
- 控制台显示 `[PublishedGame] 无法获取任何临时 URL` + `内联回退模式，已加载自包含内容，大小: 1149 字节`

### 根因分析（3层连锁bug）

**Bug 1: 本地缓存彻底丢失**
- `savePublishedGame` 在 `trySaveLS` 成功后 `deleteFromDB(gameId)`（删除 IndexedDB）
- `ensureLocalStorageSpaceForAuth()` 清空 localStorage `allinone_game_files_*` 键
- 两者同时丢失 → localStorage 和 IndexedDB 都空 → `loadGameFiles` 无本地缓存

**Bug 2: `getTempFileURL` 失败但无诊断日志**
- `getCloudHostedGameHtml` 和 `downloadFilesFromManifest` 调用 `getTempFileURL` 但不记录 status/errMsg
- 无法得知失败原因（权限/格式/文件不存在）

**Bug 3: 单文件缓存覆盖 IndexedDB**
- `loadGameFiles` 步骤④拿到 1149 字节入口 HTML 后把单文件缓存写入 IndexedDB
- 如果 IndexedDB 中曾有完整数据（但现在因 Bug1 已空），会覆盖；但更关键的是 `loadGameFilesFromCloud` 也因 Bug2 失败 → 只有单文件

### 修复（1 文件，3 处修改）

1. **Bug1 修复**：`savePublishedGame` 不再删除 IndexedDB，改为 localStorage + IndexedDB 双写冗余
   - 当 localStorage 被 auth 空间管理清空时，IndexedDB 仍有备份
   
2. **Bug2 修复**：`getCloudHostedGameHtml` 和 `downloadFilesFromManifest` 增加：
   - 详细日志：每个 `getTempFileURL` item 的 status/errMsg
   - 策略 B 回退：cloudFileID 格式失败时，尝试用 cloudPath 格式（`games/gameId/style.css`）

3. **Bug3 修复**：`loadGameFiles` 步骤④不再把单文件缓存写入 IndexedDB（只写 localStorage）
   - 完整文件集才写入两者；步骤⑥也改为双备份

## STORAGE_EXCEED_AUTHORITY 云存储权限修复

### 问题
- 另一浏览器加载游戏时，所有 `getTempFileURL` 返回 `STORAGE_EXCEED_AUTHORITY`
- `/api/v1/games/dev-token` 404（后端 API 未运行，authTokenService 尝试调用导致报错）
- iframe sandbox `allow-scripts + allow-same-origin` 安全警告

### 根因
1. **STORAGE_EXCEED_AUTHORITY**：CloudBase 云存储安全规则默认 `read: false`，未登录或权限不足的用户无法读取游戏文件
2. **dev-token 404**：`authTokenService.getToken()` 只尝试 dev-token 端点，不尝试 CloudBase Auth accessToken（优先级倒置）
3. **iframe sandbox 警告**：`allow-scripts + allow-same-origin` 组合是游戏运行必要配置，非功能性 bug

### 修复（2 文件）
1. **authTokenService.ts**：`getToken()` 改为先尝试 CloudBase Auth accessToken，再回退到 dev-token 端点
2. **publishedGameService.ts**：`STORAGE_EXCEED_AUTHORITY` 时输出明确提示，指导用户配置 CloudBase 安全规则

### CloudBase 控制台配置（用户需手动）
- CloudBase 控制台 → 存储 → 安全规则：`{ "read": true, "write": "resource.openid == auth.uid" }`

## entryHtmlContent 自包含修复（跨浏览器根本解决）

### 问题
- 跨浏览器 `getTempFileURL` 返回 `STORAGE_EXCEED_AUTHORITY`，即使安全规则已设 `{ "read": true, "write": true }`
- 回退到内联模式后，HTML 仍引用外部 `style.css`/`script.js` → 404
- 根因：`STORAGE_EXCEED_AUTHORITY` 不是安全规则问题 — `getTempFileURL` 对私有读文件仅允许上传者/管理员获取临时链接，匿名登录（跨浏览器）不满足"上传者身份"
- `entryHtmlContent` 存的是原始 HTML（含 `<link href="style.css">`），非自包含

### 修复（1 文件，2 处改动）
1. **`saveGameFiles`**：发布时将 CSS/JS 内联进 HTML → `entryHtmlContent` 为真正自包含版本
   - 构建 fileMap 从 uploadFiles
   - `<link rel=stylesheet href="style.css">` → `<style>/* inlined */\n{css}</style>`
   - `<script src="script.js">` → `<script>/* inlined */\n{js}</script>`
   - 不可内联的引用 → 移除（避免跨浏览器 404）
2. **`getSelfContainedGameHtml`**：无法内联时移除引用而非保留
   - 旧格式 `entryHtmlContent`（非自包含）的 CSS/JS 引用 → 移除（而非保留导致 404）

### 注意事项
- 已发布游戏需**重新发布**才能生成自包含 `entryHtmlContent`
- `STORAGE_EXCEED_AUTHORITY` 无法仅靠安全规则解决 — `getTempFileURL` 对私有读文件要求上传者身份
