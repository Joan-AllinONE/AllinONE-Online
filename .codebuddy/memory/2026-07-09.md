# 2026-07-09

## 跨浏览器游戏列表同步 — 最终可用方案（事件型 HTTP 云函数 + HTTP 访问服务）

### 根因（分两层）
1. **部署 404**：用户部署是 CloudBase 静态托管（`*.tcloudbaseapp.com`），`package.json` 的 `deploy:cloudbase` 只 `tcb hosting deploy dist/static`，**后端没上线**，前端 `fetch('/api/v1/games')` 打到静态托管 → 404。
2. **云函数部署报错 `Unzip codezip Failed: zip code format error`**：tcb 3.5.3 默认 `--deployMode cos`（COS 上传）在 Windows 下打的 zip 与服务端 SCF 解压不兼容。→ 改用 `--deployMode zip`（直接 ZIP 上传）。
3. **`FUNCTION_PARAM_INVALID: FunctionType invalid`**：`--httpFn` 在 tcb 3.5.3 创建的是「Web 函数」（要 `scf_bootstrap` 起 web server），而 HTTP 访问服务期望「事件型 HTTP 函数」（请求以 event 投递给 `exports.main`）。类型对不上 → 访问层报错。→ **绝不能用 `--httpFn`**。
4. **`OutOfResultSizeLimit`（单回包 1MB 限制）**：发布时把 9MB 的 `entryHtmlContent`（自包含 HTML）整段存进 `published_games` 文档，列表/详情查询把大字段带回 → 超 1MB 回包限制。→ 所有读查询 `.field({ entryHtmlContent: false })` 剔除大字段；9MB HTML 只走 **CloudBase 存储**（`cloudFileManifest` + `getTempFileURL`），文档只存元数据。

### 最终正确部署命令（事件型函数，已验证可用）
```
tcb fn deploy gamesApi --path /api/v1/games --force --deployMode zip --runtime Nodejs20.19 -e allinonegaming-d4gmsmrzz573264f6
```
- **不带 `--httpFn`**（否则 Web 函数类型冲突）。
- `--path /api/v1/games`：自动建 HTTP 访问服务路径（事件型函数可被访问服务投递 event）。
- `--deployMode zip`：绕过 Windows 下 COS 上传的 zip 解压 bug。
- `cloudbaserc.json` 里**不要写 `"type": "http"`**（会强制 Web 函数，找 `scf_bootstrap` 入口报 `Entryfile` 错）。也不要保留 `scf_bootstrap` 文件。
- 部署时若卡交互确认（`是否继续部署？(Y/n)`），用 `(echo Y & echo Y & echo Y) | tcb ...` 喂过。注意 `tcb` 是 node 脚本，不能直接 `Start-Process tcb`，要用 `cmd /c "..."` 包装。

### 给用户的关键提示
1. 浏览器硬刷新（CDN 缓存）后，任意浏览器都能看到 `published_games` 里的游戏（跨浏览器）。
2. **播放大 HTML 游戏（如 ra2 9MB）走云存储**：需确认 CloudBase 存储安全规则 `read: true`（否则 `getTempFileURL` 报 STORAGE_EXCEED_AUTHORITY，回退到文档 inline 也会因 1MB 限制 500）。
3. 旧本地游戏需重新发布一次才会进 `published_games`。
4. 前端仅剩 2 个预存在 TS 错误（`savePublishedGame` 的 `Omit<…'players'|'status'>`），esbuild 不校验，`pnpm build` 不受影响。
