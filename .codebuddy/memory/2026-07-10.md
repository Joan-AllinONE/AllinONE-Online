# 2026-07-10（五）真正根因：写操作被静态托管 413 挡掉，到不了网关

## 现象（用户第三轮）
前端已解耦 entryHtmlContent 写入，发布时仍报：
`allinonegaming-...tcloudbaseapp.com/api/v1/games/:1 413 (Payload Too Large)`
`[PublishedGame] ❌ entryHtmlContent 写入后端失败 ... Error: HTTP 404 (no backend at /api/v1/games/)`

## 真正根因（callGamesApi 候选顺序 + 构建未注入 env）
- `GAMES_API_BASE` 在生产构建中**未被注入**（无 VITE_GAMES_API_BASE），原代码回退候选为：
  1. (空) → 2. 相对路径 `/api/v1/games`（同源静态托管 tcloudbaseapp.com）。
- GET 走相对路径静态托管能通（读小响应，托管可能代理到函数，或读的是别的），故列表/详情"看起来正常"。
- 但 **POST/PATCH 大请求体（entryHtmlContent ~103KB）被静态托管直接 413 拒绝**，永远到不了真正的 API 网关 → 文档建了、entryHtmlContent 始终写不进。
- 实测 API 网关绝对地址 `https://allinonegaming-d4gmsmrzz573264f6.service.tcloudbase.com/api/v1/games` 对 100KB+ POST **完全正常**。

## 修复（src/services/publishedGameService.ts callGamesApi）
候选顺序改为**强制走网关绝对地址**：
- 主：`GAMES_API_BASE`（若设）
- 次：兜底常量 `GAMES_API_GATEWAY_FALLBACK`（硬编码网关地址，杜绝静态托管）
- 仅 `import.meta.env.DEV` 时才把相对路径 `/api/v1/games` 作为最后兜底（生产绝不走，避免 413）。
- 新增 `GAMES_API_GATEWAY_FALLBACK` 常量，确保即便 env/默认双失效也走网关。

## 验证
- 重建部署成功（build 36s）。
- 后端清理：删掉 4 条缺 entryHtmlContent 的旧记录（含 game-1783643920061 / game-1783669483216 / test-probe-*），AFTER_COUNT=0。

## 用户需注意
- 必须**重新发布**游戏才会触发新写路径把 entryHtmlContent 落库；旧文档已清空，无残留干扰。
- 成功标志：发布时控制台 `[PublishedGame] ✅ entryHtmlContent 已写入后端`（不再有 413/404）；另一浏览器播放时「使用后端文档自包含 HTML（主路径）」且无 getTempFileURL 报错。

# 2026-07-10（四）跨浏览器仍失败 → 根因在「写入端」：entryHtmlContent 从未落库

## 现象（用户第二轮反馈）
后端删空后重新发布「超级玛丽改造5.html」(game-1783643920061)，浏览器2 仍走云存储报 STORAGE_EXCEED_AUTHORITY。
直查后端：`GET /api/v1/games/game-1783643920061` → entryHtmlContent=False。即读取端主路径有，但库里没有数据。

## 真正根因（写入端 bug）
`saveGameFiles()` 中「构建自包含 HTML → patchPublishedGameOnBackend({entryHtmlContent})」整段被嵌套在
`import('./cloudbaseStorage').then(uploadGameFiles...).then(...)` 链内。
云存储本环境必败（畸形 fileID + STORAGE_EXCEED_AUTHORITY），外层 `.catch(()=>{})` 吞掉所有错误，
导致 entryHtmlContent 永远发不出去 → 后端该字段恒为 False → 读取端无米下锅只能碰云存储。

## 修复（src/services/publishedGameService.ts saveGameFiles）
把「构建自包含 HTML + 写后端」从云存储链**解耦**：
- 用本地 files 直接内联 CSS/JS → patchPublishedGameOnBackend({entryHtmlContent}) 立即写入（带成功/失败日志）。
- 云存储上传降为仅兜底，失败仅 warn。
前端重建部署（`pnpm run deploy:cloudbase`）成功。云函数上轮已部署未变。

## 用户需注意
- 必须**重新发布**游戏才会触发新写入逻辑把 entryHtmlContent 落库；旧文档(含 game-1783643920061)该字段仍空。
- 验证标志：发布时控制台 `[PublishedGame] ✅ entryHtmlContent 已写入后端`；另一浏览器播放时「使用后端文档自包含 HTML（主路径）」且无 getTempFileURL 报错。

# 2026-07-10（三）删除全部记录 + 修复 DELETE bug + 6MB 保护

## 用户需求
"彻底全清"：删后端已发布游戏 + 清本地缓存后重新发布。

## 后端删除 bug（已修复部署）
- 原 DELETE `/:id` 用 `getCollection().where({id}).remove()` → 该 SDK 下批量 where remove 返回 `removed:0` 且实际匹配不到（文档由 `.doc(id).set()` 创建，_id===id）。20 条只删掉 2 条。
- 修复（cloudfunctions/gamesApi/index.js）：
  1. DELETE `/:id` 改为 `.doc(id).remove()` 优先 + `.where({id}).remove()` 兜底，兼容 `deleted`/`removed` 两种返回字段。
  2. 新增 DELETE `/`（无 id）= 批量清空：遍历 `.field({id:true})` 列表逐个 `.doc(gid).remove()`。
  3. 详情 GET 加 6MB 保护：entryHtmlContent>5MB 时剔除并标记 `entryHtmlTooLarge`，避免整份文档超 HTTP 回包 6MB 上限触发 FUNCTION_INVOCATION_FAILED（红警等大游戏会踩到）。
- 结果：`DELETE /api/v1/games` → removed:17，REMAINING=0 ✓。

## 本地清理（交给用户在浏览器控制台跑）
本地存储结构：localStorage(钱包/凭证/交易/平台商店/已发布游戏缓存/种子标记) + IndexedDB 仅 1 库 `AllinONE_GameFiles`(gameFileDb.ts，游戏文件缓存)。VoucherDatabase 实为 localStorage。
给了脚本：localStorage.clear()+sessionStorage.clear()+indexedDB.deleteDatabase('AllinONE_GameFiles')+reload。清后种子自动重建钱包/凭证/商店。

## 遗留提醒
- entryHtmlContent>5MB 的超大游戏：详情接口会剔除内联 HTML 回退云存储（本环境不可靠）→ 需分片方案，暂建议先发小体积游戏。

# 2026-07-10 修复跨浏览器"游戏无法加载"（manifest 丢失）

## 现象
上轮修好跨浏览器目录同步后，浏览器2 目录能显示但游戏打不开。
日志："[PublishedGame] 无 cloudFileManifest，回退到内联方案" → "本地未找到，使用 cdnUrl 回退" → 加载失败。

## 根因
1. 播放走 `getCloudHostedGameHtml`，需文档里的 `cloudFileManifest`（云存储文件清单）→ getTempFileURL 加载。
2. 上轮已把 `entryHtmlContent` 从所有读取剔除（避免 1MB 回包限制），内联兜底路径已死 → 唯一通道是 manifest。
3. 但 manifest 是发布时用 **PATCH** 方法回写的，而 CloudBase HTTP 访问服务对 PATCH 转发不稳定 → manifest 未落库。
4. 且云函数 POST 用 `.doc().set()` 整份覆盖，即使 PATCH 先到也会被 POST 抹掉（POST 与 manifest 回写并发）。

## 修复（3处，已部署验证）
1. `cloudfunctions/gamesApi/index.js`：新增 `upsertMerge(id,data)`（按字段 id 合并更新，不存在则 doc().set 创建，保留主键 id）。POST 与 PATCH 都改用合并 upsert，不再整份覆盖 → 并发写入互不覆盖。
2. `src/services/publishedGameService.ts` `patchPublishedGameOnBackend`：改走 `callGamesApi('POST','/',{id,...partial})`（POST 已验证可靠，弃用 PATCH）。
3. 同文件 `getCloudHostedGameHtml`：文档读取优先走后端 API `callGamesApi('GET','/'+gameId)`（管理员 SDK 可靠，不受客户端 DB 安全规则影响），失败才回退客户端 DB。

## 验证
`pnpm run deploy:cloudbase` 前端+云函数全部部署成功。
端到端：POST 建档(name) → POST 合并(manifest) → GET 详情同时含 name+manifest ✓。DELETE 生效（removed:0 是计数显示偏差，实际已删）。

## 用户需注意
- 修复前发布的旧游戏（如 game-1783637451126）文档缺 manifest，需**重新发布一次**才能跨浏览器加载（文件已在云存储，只是清单没落库）。新发布的游戏直接正常。
- 云存储安全规则 read 需为 true，否则 getTempFileURL 报 STORAGE_EXCEED_AUTHORITY。
- 遗留噪音（非致命）：`/api/v1/games/dev-token` 404（authTokenService/tokenManager 老路径，callGamesApi 本身免 token）；`/api/redeem/sync` 404（redeem 后端未部署）；AI hunyuan-exp 403。

# 2026-07-10（续）游戏仍无法加载 → 真正根因：云存储整条链路坏掉，改用后端文档内联 HTML

## 现象
目录同步 OK（后端 20 条），但浏览器2 播放报 `getTempFileURL ... status=STORAGE_EXCEED_AUTHORITY`。
用户困惑：浏览器1 地址是 `https://...tcloudbaseapp.com/game/...`（SPA 页面 URL），浏览器2 控制台是 `cloud://...616c-allinonegaming-.../...html`（云存储 fileID）——其实两者不同层，不是 bug。
真正问题在 fileID 本身畸形：`cloud://allinonegaming-d4gmsmrzz573264f6.616c-allinonegaming-d4gmsmrzz573264f6-1303031594/...`（`.616c-` 重复 env），叠加存储 read 安全规则未放行 → getTempFileURL 必败。

## 根因
云存储 `getTempFileURL` 在本环境根本不可用（畸形 fileID + STORAGE_EXCEED_AUTHORITY），而 `getCloudHostedGameHtml` 的主路径依赖它。
更关键：发布流程其实**早已把自包含 HTML（`entryHtmlContent`，CSS/JS 已内联，~87KB）写进后端文档**（publishedGameService.ts:672-675 `patchPublishedGameOnBackend(gameId,{entryHtmlContent})`），但：
- 云函数 `gamesApi` 详情 GET 用 `.field({entryHtmlContent:false})` **把字段剔除了** → 前端永远拿不到。
- `getCloudHostedGameHtml` 在 `urlMap.size===0` 时**提前 return null**，根本没走到 entryHtmlContent 兜底分支。

## 修复（2处，已部署验证）
1. `cloudfunctions/gamesApi/index.js` 详情 GET：去掉 `.field({entryHtmlContent:false})`，改为返回完整文档（列表 GET 仍剔除，避免 N×大HTML 撑爆回包）。
2. `src/services/publishedGameService.ts` `getCloudHostedGameHtml`：在 manifest 逻辑前加**主路径**——若 `doc.entryHtmlContent` 是非空 HTML 串（长度>200 且匹配 `<html|<body|<script|<!doctype`），直接 `return entryHtmlContent`，完全绕过云存储，天然跨浏览器。

## 验证
- `pnpm run deploy:cloudbase` 前端+云函数均部署成功。
- 详情 API 直接验证：`GET /api/v1/games/game-1783638655909` 返回 `entryHtmlContent` 长度 86930 字节 ✓。
- 浏览器2 现走主路径：拿到后端内联 HTML → srcDoc 渲染，不再碰云存储。

## 结论 / 用户需注意
- **新发布（含本会话 game-1783638655909）的游戏现在可直接跨浏览器加载**，无需改任何云存储安全规则。
- 旧游戏若文档里没有 `entryHtmlContent`（极早期发布的），仍会回退到云存储而失败 → 重新发布一次即可（发布流程会自动写入 entryHtmlContent）。
- 云存储整条链路在本环境不可靠，已不再作为播放主路径；保留为无 entryHtmlContent 时的兜底。
