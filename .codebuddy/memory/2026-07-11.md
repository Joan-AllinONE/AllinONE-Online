## 跨浏览器游戏内容共享失败修复（publishedGameService.ts）

**根因（两层）：**
1. **413 Payload Too Large**：游戏入口 HTML（entryHtmlContent ~100KB+）发布时通过 CloudBase 网关（service.tcloudbase.com）POST，被网关 ~100KB 请求体限制直接拒绝（服务端限 150MB 无关）。结果元数据写入、内容永远写不进后端 → 跨浏览器加载不到内容。
2. **读取路径 bug**：`getCloudHostedGameHtml` 取 `doc = json.data`，但服务端 GET /:id 返回结构是 `{ data: { game } }`，导致 `doc.entryHtmlContent` / `doc.cloudFileManifest` 永远 undefined，即便写进去了也读不到。
3. 附带 `loadEntryHtmlFromDocument` 用 `.field({ entryHtmlContent: false })` 错误排除了要读的字段。

**修复：**
- 新增 `gzipToBase64`/`gunzipFromBase64`（用 CompressionStream，前缀 `__GZ__`，不支持时退回原样）。
- `patchPublishedGameOnBackend` 自动 gzip 压缩 entryHtmlContent（>80KB），绕过网关限制。
- `getCloudHostedGameHtml` 修正为 `doc = json.data.game ?? json.data` 并解压 entryHtmlContent。
- `loadEntryHtmlFromDocument` 改为 `.field({ entryHtmlContent: true })` 并解压返回。

**已知限制：** 后端仍用内存库（USE_MEMORY_DB=true），重启即丢数据。若需持久化跨浏览器共享，需接 PostgreSQL 或云存储（读权限 STORAGE_EXCEED_AUTHORITY 需控制台安全规则设为 {"read": true}）。

**改动文件：** src/services/publishedGameService.ts（仅此一处，未动服务端）。

## 回归"CloudBase 云存储网盘方案"（用户要求，真跨浏览器共享）

**背景：** 用户要求放弃后端 server 托管方案，回归 uploadFile→games/{gameId}/→getTempFileURL→URL重写→srcDoc 的原始方案，选定"真跨浏览器共享：公开读 + 永久公开 URL"。

**当前代码状态确认：** publishedGameService.ts 已是纯 CloudBase 版本（saveGameFiles 走 uploadGameFiles 云存储，loadGameFilesFromCloud 走 getTempFileURL+manifest）。cloudbaseStorage.ts 上传路径本就是 games/{gameId}/{fileName}（无需改）。真正缺失的是被删掉的 URL 重写加载函数 getCloudHostedGameHtml。

**本次改动（2 文件，0 新 lint 错误，vite build 28s 通过）：**
1. `publishedGameService.ts` 新增：
   - `getCloudHostedGameHtml(gameId)`：读 cloudFileManifest → getTempFileURL 批量取(打开时仅调1次) → `stripUrlSignature()` 去签名得永久公开 URL → 选最佳入口 HTML fetch → `rewriteRelativeUrls()` 重写相对路径 → 返回给 srcDoc。子资源零鉴权。
   - 辅助：`stripUrlSignature`、`pickBestEntryFromManifest`(排除 css/style/helper 等辅助文件，优先 dist/index.html)、`rewriteRelativeUrls`(匹配 href/src，跳过 http/data/blob/#)。
   - default export 补 getSelfContainedGameHtml + getCloudHostedGameHtml。
2. `GamePlay.tsx`：
   - 删除后端残留：reuploadGameFiles 函数、getToken import、server/baseUrl 分支、serverUnavailable state。
   - 加载优先级改为：external cdnUrl → **getCloudHostedGameHtml（云托管URL重写）** → getSelfContainedGameHtml（内联兜底）→ cdnUrl。
   - iframe 渲染删 server 分支；establishChannel/URL参数下发 useEffect 移除 baseUrl 依赖。

**关键设计（去鉴权原理）：** 存储设公开读后，getTempFileURL 返回的 URL 去掉 `?q-sign...` 签名参数即为永久公开 URL，可直接访问。入口打开时批量调1次 getTempFileURL 拿 host，子资源全部走无签名永久 URL → 彻底消除"每个子资源反复鉴权"。比硬拼 COS host(要猜 region)更可靠。

1. CloudBase 控制台 → 存储 → 安全规则设公开读 `{"read": true, "write": "auth != null"}`（否则跨浏览器 getTempFileURL 报 STORAGE_EXCEED_AUTHORITY / 去签名 URL 403）。
2. 旧游戏需**重新发布**以生成 cloudFileManifest（含 dist/ 编译版入口 HTML + 全部子资源上传到云存储）。
3. 部署：`pnpm run build:client` → `tcb hosting deploy dist/static -e allinonegaming-d4gmsmrzz573264f6`。
