## 修复：道具工坊上传 SOP 文档后刷新/换浏览器丢失

**症状**：凭证系统 → 道具凭证 → 道具工坊，选择游戏后上传 SOP 文档（.md），自动保存后刷新页面或换浏览器均看不到。

**根因**：`src/components/ugc/AIDialog.tsx` 的 `handleSopFileChange` 上传 SOP 时调用 `savePublishedGame({...game, sopDocument})`，该方法靠**非阻塞** `writeQueue.enqueue` 落云，仅更新本地缓存。而 `getPublishedGames()` 每次都会触发后台 `refreshGamesFromCloudBase()` **无条件用云端覆盖本地缓存**。writeQueue 的 upsert 是异步的（约 500ms~数秒才落云），SOP 保存后触发的云刷新往往先于 upsert 落云执行，云端此时没有 `sopDocument`，于是把本地刚保存的值覆盖掉；跨浏览器设备无本地缓存，直接读云端（缺字段）也看不到。

**修复**（双保险，改动文件 `src/services/publishedGameService.ts` + `src/components/ugc/AIDialog.tsx`）：
1. `refreshGamesFromCloudBase()` 改为**合并**本地缓存的 `sopDocument`/`itemSop` 字段——云端为权威，但云端缺失的 SOP 字段用本地值补齐，避免云刷新覆盖未落云的本地写入。
2. `savePublishedGame` 新增 `opts.waitForCloud`；AIDialog 上传 SOP 时传 `{ waitForCloud: true }`，改用 `writeQueue.enqueueAndWait` **阻塞等待落云**再返回，消除竞态，保证跨浏览器可见。
3. SOP 保存失败时增加 `toast.error` 提示。

**验证**：需 `pnpm build` + 上传 SOP → 刷新/换浏览器确认仍可见。注意 publishedGameService.ts 264-275 行存在**预存**类型错误（`game.players`/`game.status` 在 `Omit<...>` 类型上不存在），因 `noEmitOnError:false` 不阻断构建，未改动。

## 更正（同日续）：上述 CloudBase 方案在部署环境仍无效 —— 真正根因是 CloudBase 数据库 auth 已损坏

**重新定位根因**：部署环境是 `node server.js` + `USE_MEMORY_DB=true`（内存库后端 API `/api/v1/games`），**并非** CloudBase。CloudBase JS SDK auth 已坏（`auth.call is not a function`），`published_games` 集合写入永远失败 → 库里 0 条 → 跨浏览器（及后台云刷新）永远读不到 SOP。之前"合并/阻塞等待落云"的修复是在一个根本写不进去的存储上做优化，故仍无效。游戏文件（`/upload` + `/files/*`）是另一条**已部署且跨浏览器可用**的通道，故云存储文件可见但 published_games 元数据不可见。

**真正生效的修复**（改 `src/services/publishedGameService.ts`）：把 SOP 文档当作游戏文件 `sop/sop.md` 存到后端文件通道，彻底绕开坏掉的 CloudBase 数据库：
- 新增 `getBackendSopToken()`：`POST /api/v1/games/dev-token`（无需 JWT，返回 dev JWT）签发 token。
- 新增 `saveSopToBackend(gameId, md)`：`POST /:gameId/upload`（Bearer token）上传 `sop/sop.md`。
- 新增 `loadSopFromBackend(gameId)`：`GET /:gameId/files/sop/sop.md` 读取（公开路由，无 JWT）。
- `savePublishedGame` 当 `newGame.sopDocument` 存在时调用 `saveSopToBackend` 同步落盘后端（失败仅告警，保留本地缓存兜底）。
- `refreshGamesFromCloudBase` 合并后对缺失 `sopDocument` 的游戏从后端文件补齐。
- `AIDialog.tsx` 挂载加载 SOP 时，本地/云端无值则 `loadSopFromBackend` 兜底（权威来源）。

**验证（已实测通过）**：
- 本地 `USE_MEMORY_DB=true PORT=3000 node server.js` + curl 实测三端点：dev-token 发 token → upload 返回 `saved:1` → GET 读回精确 markdown。✓
