## 本地预览模式（发布中心）已实现

用户需求：发布游戏前先在浏览器本地真实运行测试，反复修改直到无 bug 再发布，避免"上传即发布、一次发布带 bug 上线"。用户确认"不需要平台技能接线、按钮放 Review/发布区、草稿单一覆盖"。

### 实现要点
- 新增 `src/publishing-center/local/localPreviewService.ts`：`buildLocalPreview()` 复用 `PublishingPipeline.injectProtocolIntoFiles` 注入协议层+SDK（与发布一致），路径归一化，写入 IndexedDB（`saveToDB('local-preview-draft', json)`，仅本地，**零污染**）；`clearLocalPreview()` 清理草稿。草稿键固定 `local-preview-draft` 覆盖式写入。

- `public/gameFileServiceWorker.js`：`handleGameFileRequest` 开头对 `gameId` 以 `local-preview` 开头的请求短路——跳过后端与缓存，仅 `idbGet(gameId)` 从 IndexedDB 回放（SW 用精确键读取，写入键即 `local-preview-draft`，直接命中）。
- `PublishingCenter.tsx`：配置步骤 Footer「一键发布」旁新增「本地预览」按钮 → 打开预览弹窗（iframe `src=/api/v1/games/local-preview-draft/files/<entry>`，含「重新生成」「测试合格去发布」）；发布成功后 `await clearLocalPreview()` 清理草稿。

## 🐞 修复：LF2 兑换道具"用不了/暂无用户" + /api/redeem/sync 429 雪崩

用户反馈：游戏能加载后，使用道具（如回血）屏幕显示"暂无用户"，控制台 `/api/redeem/sync` 429。

### 根因
1. **道具被白白消耗（核心）**：`AllinONE Online/lf2-flat5/index.html` 的 `useCustomPowerUp` 不论效果成败都 `customPowerUps.splice` 删除道具。在战斗未开始（无角色）时点道具，heal handler 返回 `{success:false, message:'暂无玩家，请先开始游戏'}`（用户读作"暂无用户"），道具照样消失 → "兑换的道具却用不了了"。
2. **429 雪崩**：`server.js` `generalLimiter`（100 次/15 分钟，覆盖所有 `/api/`）把后台高频 `/api/redeem/sync` 计入额度，耗尽后连带把 `/api/redeem/verify`、`/api/redeem/use` 也限成 429，正常兑换/使用会失败。

### 修复
- `server.js`：generalLimiter `max` 100→300，并对 `/api/redeem/sync` 加 `skip`（不占公共额度）；strictLimiter `max` 10→30（verify/use）。
- `AllinONE Online/lf2-flat5/index.html`：`useCustomPowerUp` 重写——效果失败【不消耗】道具；当 `window.myGame.getPlayers()` 为空时轮询等待最多 4 秒再执行（提示"⏳ 等待战斗开始…"），仍无角色才提示清晰错误并保留道具。

### 生效条件
- 429 修复：重启 `node server.js` 立即生效（server 端）。
- LF2 修复：`AllinONE Online/lf2-flat5` 是发布源，需**重新发布 LF2**（发布中心重传该目录）→ SW 从 IndexedDB 回放新 HTML；浏览器硬刷新（Ctrl+Shift+R）GamePlay 页。
- 注意：回血/无敌等效果需"已开始一局战斗且存在角色"才生效，在菜单点会等待/提示，属正常。

## 🐞【纠正】LF2 道具"暂无玩家"真正根因：manager.match 从未赋值（19 晚复核）

用户反驳：已开战、已受伤，用回血仍报"暂无玩家" → 说明不是"等待角色出现"的问题，而是 `getPlayers()` 永远拿不到角色。

### 真正根因（已定位并修复）
- `LF/manager.js` 的 `start_match(config)` 创建了 `const match = new Match(...)` 并 `match.create(...)`，但**从未把 match 赋给 `this.match`**。
- `flf-boot.js` 的 `getMatch()` 返回 `manager.match`，因此 `manager.match` **永远是 null** → `getPlayers()` 永远返回 `[]` → 任何 heal/武器/无敌道具都报"暂无玩家"。
- 之前（上一条）的"等待角色 4 秒"是错误方向：没有角色可等，因为 match 引用本身就是 null。

### 修复
- `LF/manager.js` `start_match`：在 `match.create({...})` 之后、return 之前加 `this.match = match`（含注释）。`start_debug`/`start_demo` 都走 `start_match`，一并生效。
- `index.html` 的 `useCustomPowerUp` 已加固"失败不消耗道具"（仍保留，属合理安全网）。

### 验证/生效
- 纯 JS 游戏逻辑改动，重启游戏即生效；若玩的是发布版，需**重新发布 LF2**（重传 `AllinONE Online/lf2-flat5` 目录）。
- 教训：用户"已开战仍无效"的反馈直接推翻了"无角色"假设，应去查 match 引用本身是否被正确设置，而非加大轮询等待。

### 429 仍属真实问题（非主因）
- `/api/redeem/sync` 429 是独立真实问题，server.js 限流放宽修复有效，保留。但它不是"暂无玩家"的原因。

### 补救：还原 index.html 误改（用户追问后）
- 用户问"误改的地方改回来了吗" → 确认：server.js 限流**保留**（真实独立问题）；index.html 的 `useCustomPowerUp` **已还原为诊断前的原始实现**（删除了基于错误假设的"等待 4 秒"轮询逻辑，其现在无意义；`manager.match` 修复后原始逻辑在战斗中使用道具即正常生效并消耗道具）。
- 当前 LF2 修复仅剩 `LF/manager.js` 的 `this.match = match` 一处（真正根因）。
