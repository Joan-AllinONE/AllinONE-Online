# 2026-07-24

## 修复：预设道具（heal/invincible 等）在 LF2 游戏中不可用

**用户反馈**：上一版（2026-07-23）的"effect 改名 `_local_<x>` + effectCode 沙箱脚本"方案使道具无法使用。控制台日志显示 Effect Engine 收到 `heal` → 委托 CustomEvent → SDK 注入 `_local_heal`，但游戏（LF2 `lf2-flat5/index.html`）内置 `EFFECT_HANDLERS` 只认 `heal`/`invincible` 原名，不认 `_local_` 前缀。

**根因**：
1. LF2 游戏的 `EFFECT_HANDLERS`（`index.html` 第179行）内置 `invincible`/`heal`/`super_mode`/`restore_mp`/`give_weapon` 等键，使用 `players.forEach` → 全场误伤（含 CPU 对手）
2. effect 改名为 `_local_heal` 后，游戏 `handleRedeemedItem` 仍会把道具加到 customPowerUps（用 `voucherData.effect`），但点击时 `useCustomPowerUp` 走 effectCode 沙箱注册路径
3. effectCode 沙箱（LF2 `registerDynamicEffect`）有隐患：`new Function('game',...)` 在注册时捕获 `window.myGame`，game 引用可能陈旧；安全检查过严也可能拒注册 → 道具不可用

**新方案（LocalPatcher，2026-07-24）**：放弃 effectCode 沙箱 + `_local_` 前缀，改用原地替换游戏 handler 表。
- 保持原始 effect 名 → 游戏识别并加到 customPowerUps（props 栏可见）
- Effect Engine 注入 LocalPatcher（IIFE）：定义 `_LOCAL_HANDLERS`（heal/invincible/super_mode/restore_mp/give_weapon 本地玩家版本，用 `_getLocalPlayer` 筛除 AI 角色，仅对第一个人类角色调 `window.myGame` 单角色 API）
- LocalPatcher 轮询 `window.allinoneAdapter`（500ms × 60 = 30s 超时），就绪后 `_patchAdapter` 原地替换 `adapter.handlers[name]`（`allinoneAdapter.handlers` 是游戏内部 `EFFECT_HANDLERS` 的引用，修改同一对象）→ `useCustomPowerUp` 点击时命中替换后的 handler
- 用 `__allinoneLocalPatched` 标志防重复替换；`__allinoneLocalPatchStarted` 防 patcher 重复启动
- 暴露 `window.AllinONE.patchLocalPlayerHandlers(adapter)` 供调试

**改动文件**：仅 `src/publishing-center/core/PublishingPipeline.ts`（平台侧，未改游戏文件）
- Effect Engine（`generateEffectEngine`）：删除 `_LOCAL_PLAYER_EFFECT_CODES` 映射 + `__LOCAL_EFFECT_CODES__` 全局暴露，替换为 LocalPatcher IIFE
- Mode A SDK（`generateAllinoneSDK`）：删除 `_local_` 前缀 + effectCode 注入逻辑，CustomEvent 用原始 effect 名 + `res.voucherData || {}`
- Mode B Protocol Bridge（`generateProtocolBridge`）：同 Mode A 删除 effectKey/localEffectCode 逻辑；删除 `_LOCAL_PLAYER_EFFECT_CODES_B` 映射
- 各 effect handler 注释/console.log 从"+ effectCode"改为"LocalPatcher 接管"

**验证**：`tsc --noEmit -p tsconfig.json` PublishingPipeline.ts 0 错误（其余报错均为预存的其他文件 TS6133 等无关错误）；read_lints 0 错误。

**注意**：本方案依赖游戏暴露 `window.allinoneAdapter.handlers`。LF2 暴露了（`index.html` 第397行），Match3 等其他游戏若未暴露则 LocalPatcher 30s 后 warn 跳过，道具退回用游戏内置 handler（可能有 forEach 全场误伤，但至少可用）。

## 下午修复：LF2 `.con` 属性名 bug（"暂无本地玩家"）

**用户反馈**：LocalPatcher 成功替换 handler，但道具点击后显示"暂无本地玩家"，道具仍无效果。

**根因**：LF2 引擎角色的 controller 属性名是 `.con`（不是 `.controller`）。`_getLocalPlayer` 检查 `p.controller` → 永远 undefined → 全部跳过 → 返回 null → "暂无本地玩家"。

LF2 controller 结构：
- 人类：`char.con.type = 'keyboard'` 或 `'touch'`（定义在 `controller.js` 第143行）
- AI：`char.con.type = 'AIcontroller'`（定义在 `LF/AI.js` 第211行，`AIcon.prototype.type`）
- 角色用 `char.con` 引用 controller（非 `char.controller`），见 `livingobject.js` 第307行、`combodec.js` 第72行

**修复**（`PublishingPipeline.ts` 三处 `_getLocalPlayer`）：
1. Mode B Protocol Bridge `_getLocalPlayer`（line ~1206）
2. Mode A Effect Engine `_getLocalPlayer`（line ~1708）
3. LocalPatcher IIFE `_getLocalPlayer`（line ~1732）

每处改动：
- `ctrl = (p && p.con) || (p && p.controller)` — 兼容 LF2 `.con` 和其他游戏 `.controller`
- 人类 controller type 显式匹配：`'keyboard'`/`'touch'`/`'gamepad'`/`'network'`
- 非 AI 但已知 type 也接受（保守 fallback）
- 无 controller 信息时 fallback `players[0]`（P1 通常为人类）

0 lint 新增错误。
