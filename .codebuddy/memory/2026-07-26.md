## 关键修复：SW 硬编码兜底 + install 预加载 config.js（2026-07-26 15:00）

**问题根因**（从用户无痕浏览器控制台分析）：
- 所有 `/api/*` 返回 404/503 → SW 的 Cache Storage 为空（首次访问/incognito）→ `getApiBaseUrl()` 返回空字符串 → SW 放走请求走默认网络 → CloudBase 静态托管无后端 → 404
- LF2 入口 HTML 503 → 同因：SW 没有后端地址 → 不代理 → CloudBase rewrite → 503
- `POST /dev-token` 404 → 同因

**修复内容**：

### 1. SW 硬编码生产环境兜底（`PRODUCTION_BACKEND_URL`）
- `getApiBaseUrl()` 在 CloudBase 域名下（`origin.includes('tcloudbaseapp.com')`）直接返回硬编码云函数 URL
- 开发环境（localhost）返回空字符串 → vite 代理处理
- **彻底解决了首次访问/incognito 的 404/503 问题**——不依赖 Cache Storage 或 config.js

### 2. SW install 预加载 config.js
- `fetch('/config.js?_sw_init=' + Date.now())` → 解析 `__API_BASE_URL` → 写入 Cache Storage
- `skipWaiting()` → SW 立即激活
- 与硬编码兜底配合：即使预加载失败（CDN 缓存旧版返回空 URL），硬编码兜底仍生效

### 3. `getApiBaseUrl()` 兼容两种字段名
- `data.apiBaseUrl`（main.tsx syncApiConfigToSW 写入）和 `data.baseUrl`（install 预加载写入）

**CDN 缓存问题**：
- `config.js`（不带 query）→ CDN 缓存旧版（`__API_BASE_URL = ''`）
- `config.js?v=20260726` → CDN 返回正确版本（`__API_BASE_URL = 'https://...service.tcloudbase.com/api'`）
- **但不再影响功能**：SW 硬编码兜底确保即使 config.js 返回空字符串，SW 也能代理到云函数

## SW v4：修复 duplex + CORS type 不匹配（2026-07-26 17:00）

**问题**：游戏可以加载但无法正常运行。控制台暴露两个 SW 代理 bug：

### Bug 1: duplex 错误
```
TypeError: Failed to execute 'fetch' on 'WorkerGlobalScope': 
The `duplex` member must be specified for a request with a streaming body
```
- **根因**：`proxyToBackend` 中 `init.body = req.clone().body` 是 ReadableStream，fetch 要求显式 `duplex: 'half'`
- **修复**：`init.duplex = 'half'`

### Bug 2: CORS type 不匹配
```
The FetchEvent for ".../lf2-flat5/index.html" resulted in a network error response: 
a "cors" type response was used for a request whose mode is "same-origin"
```
- **根因**：SW 用 `mode: 'cors'` 代理跨域请求 → 返回 Response type 是 `'cors'`。但原始请求是 `same-origin` 模式 → 浏览器要求 response type 也必须是 `'basic'` → 不匹配 → network error
- **修复**：检测 `resp.type === 'cors'` 时，重新构造 Response（去掉 CORS 头，body 透传）→ type 变为 `'basic'` 匹配原始请求模式

**SW 文件版本**：`gameFileServiceWorker-v4.js` → `gameFileServiceWorker-v5.js`

## SW v6：修复 Mixed Content + CloudStudio URL 污染（2026-07-26 19:00）

**问题根因**：SW install 事件预加载 `config.js` → CDN 返回**旧版 config.js**（含已废弃的 CloudStudio HTTP URL `http://c647c55bf7ac4a28be18134cc8890844.codebuddy.cloudstudio.run:5000/api`）→ 写入 Cache Storage → 后续所有请求代理到这个 HTTP URL → **Mixed Content 被浏览器阻止**（HTTPS 页面不能请求 HTTP 资源）

**修复内容**（`gameFileServiceWorker-v6.js`）：

### 1. `isValidBackendUrl()` 校验函数
```javascript
function isValidBackendUrl(url) {
  if (!url.startsWith('https://')) return false;  // 必须 HTTPS
  if (url.includes('codebuddy.cloudstudio.run')) return false;  // 拒绝 CloudStudio URL
  return true;
}
```

### 2. `getApiBaseUrl()` 校验 + 清除无效缓存
- 从 Cache Storage 读取 URL 后，用 `isValidBackendUrl()` 校验
- 无效 URL → 清除 Cache Storage 中的旧条目 → 使用硬编码 `PRODUCTION_BACKEND_URL`

### 3. 移除 install 事件的 config.js 预加载
- 旧代码：`fetch('/config.js?_sw_init=...')` → CDN 可能返回旧版 → 污染 Cache Storage
- 新代码：install 事件只清除旧 Cache Storage 条目 + `skipWaiting()`
- 依赖 `syncApiConfigToSW()`（页面加载后写入正确 URL）和 `PRODUCTION_BACKEND_URL`（硬编码兜底）

**关键教训**：CDN 缓存对 config.js 极其顽固（多次删除+重新上传仍返回旧版）。SW 不能信任 CDN 缓存的 config.js。硬编码 `PRODUCTION_BACKEND_URL` 是唯一可靠的兜底方案。

**SW 文件版本**：`gameFileServiceWorker-v5.js` → `gameFileServiceWorker-v6.js`（CDN 缓存旧版 v5，改文件名强制刷新）

## 根因发现：JS 文件在云存储中被存成逗号分隔字节值（2026-07-26 20:00）

**问题根因**：
- `saveGameFiles()` 中 `String(f.content)` 对 `Uint8Array` 返回 `"47,42,10,..."`（逗号分隔字节值），而非 JS 代码
- 游戏文件（require.js、flf-boot.js 等）上传到云存储后，内容变成了 `47,42,10,32,82,101,...` 格式
- 云函数原样返回这些内容 → 浏览器收到的是字节值文本，不是可执行的 JS
- `index.html` 不受影响（它是 string 类型，`String(string)` 返回原样）

**修复**（`src/services/publishedGameService.ts`）：
```typescript
// 修复前（bug）：
content: typeof f.content === 'string' ? f.content : String(f.content),
// String(uint8Array) → "47,42,10,..." ❌

// 修复后：
if (typeof f.content === 'string') {
  content = f.content;
} else if (f.content instanceof Uint8Array || f.content instanceof ArrayBuffer) {
  const bytes = f.content instanceof Uint8Array ? f.content : new Uint8Array(f.content);
  const isText = /\.(html?|js|mjs|ts|css|json|xml|txt|md|csv|svg|con|cfg|ini)$/i.test(filePath);
  if (isText) {
    content = new TextDecoder('utf-8').decode(bytes);  // ✅ 正确解码为 JS 文本
  } else {
    content = bytes;  // 二进制文件传原始 bytes
  }
}
```

**同步修复**（`src/services/cloudbaseStorage.ts`）：`uploadGameFiles` 支持 `Uint8Array` 二进制内容（`new File([bytes.buffer], ...)`）。

**需要重新上传游戏**：云存储中的 JS 文件已经是字节值格式，必须用修复后的代码重新上传游戏才能恢复正确的 JS 内容。
