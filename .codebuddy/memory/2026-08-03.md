用户确认方案后执行。根因：凭证写入全走 writeQueue → CloudBase 浏览器端 auth 损坏 → 线上永落库；另一浏览器 syncFromCloudBase 拉到 0 条 → 显示「未铸造/已售罄」。

- 新增 `src/services/voucherBackend.ts`：走 gamesApi 云函数（永久 URL `/api/v1/games/<collection>`），GET 分页 + POST upsert + DELETE。
- `src/voucher-system/storage/VoucherDatabase.ts`：syncVouchersToCloud/syncTransactionsToCloud 改调 saveVoucherToBackend；syncFromCloudBase 改 loadCollectionFromBackend 分页 + 云端为准覆盖；移除 writeQueue 导入。
- `src/services/voucherItemService.ts`：templates/purchases 写入改 saveVoucherToBackend、读取改 loadCollectionFromBackend 分页；移除 writeQueue 导入。
- `cloudfunctions/gamesApi/index.js`：新增 vouchers/voucher_templates/purchases/voucher_transactions 路由（置于游戏 id 路由之前避免被 game not found 拦截）；新增 parseQuery；支持 GET/POST/DELETE。

验证：pnpm build 成功；云函数 tcb deploy --force 成功；GET 返回真实凭证数据、POST/DELETE 测试通过、测试数据已清理。
约束：绝不回退 writeQueue、绝不保留 limit(500)、用永久云函数 URL。

## 修复：活动中心（ActivityCenter）页面崩溃

用户报活动中心无法显示：控制台 `api/v1/activities/:1` 404 + `n.filter is not a function`。

根因：线上 HTTP 访问服务只路由 `/api/v1/games/*` 到 gamesApi，activities 前缀无路由 → 404；SW 对非游戏 `/api/*` 返回 `{data:null}` 非数组 → 前端 `.filter` 崩溃。

改动（详见 MEMORY.md「活动中心修复」小节）：
- 云函数 gamesApi 新增 activities 路由（种子列表/leaderboard/claim），走 `/api/v1/games/__activities` 隧道（`path` 改 let + 前缀重写）。
- 前端 `ACTIVITY_API_BASE='/api/v1/games/__activities'`；`fetchActivities`/`useActivity` 防御非数组。
- SW bump v8→v9（activities 代理分支）+ main.tsx 注册改名。

验证：线上三端点（list/leaderboard/claim）全部 200/成功；前端已重新 build + hosting deploy。用户需强制刷新（Ctrl+Shift+R）生效。
踩坑：const path 不可重新赋值（500）、HTTP 访问服务只认 /api/v1/games 前缀（需隧道）、SW 必须改文件名绕 CDN。
