## 跨浏览器数据同步全平台修复（Bug 013 泛化，B0-B7 全部完成并部署）

### 背景
用户反馈「凭证系统的游戏提案也不能同步数据」。全量排查确认：除已修的凭证外，
共 11 个模块 / 17 个集合存在**同一根因** —— 浏览器端 CloudBase JS SDK auth 损坏
（`auth.call is not a function`），写入全走 `writeQueue` → 线上永不落库；

2. **不需要**孤儿数据迁移

## 2026-08-10 跨浏览器游戏文件不可用修复（新上传游戏 404/503）

### 问题现象
用户在 CloudBase 静态托管域名上传新游戏 `game-1786321687027`，跨浏览器打开报
"游戏文件不可用：后端离线且本地无缓存"。旧游戏（lf2）正常，新游戏 `index.html` 404→503。
控制台另有 `vouchers`/`store_products` 大量 500 刷屏。

### 根因（与 2026-07-25 同类但更明确）
1. **新游戏文件只存云存储（匿名不可读）**：`saveGameFiles` 仅把文件 uploadFile 到云存储，
   `cloudbaseStorage.ts` 的 `fileManifest.push` 缺 `cloudPath`；云函数文件服务路由用
   `getTempFileURL` 取下载 URL —— 匿名用户触发 `STORAGE_EXCEED_AUTHORITY` → 文件取不到 → 404/503。
   （之前旧游戏能玩是因为当时把文件写进了后端 `dist/static/game-files` 目录 + IndexedDB）
2. **500 刷屏**：云函数 SYNC_COLLECTIONS 的 GET 分支和 POST 单条分支无 try/catch，底层抛错直通外层 500。

### 修复方案（与"直接存 DB 文档字段" proven pattern 一致）
- **新增 `game_files` 集合**（跨浏览器匿名直读，绕开云存储权限限制）：
  - 云函数新增 `POST /__files` 隧道：接收 `{gameId, files:[{path,content}]}`，
    写 `db.collection('game_files').doc(gameId).set({files})`。文本直接存；二进制以 `__BINARY_BASE64__` 前缀的 base64 字符串存。
  - 云函数文件服务路由 `GET /:id/files/*` **优先**从 `game_files` 读内容返回
    （`Buffer.from(content,'utf8')` 还原），失败才回退云存储 getTempFileURL/downloadFile。
  - 前端 `publishedGameService.ts` 的 `saveGameFiles`：发布时把 `storableFiles`（含 path+content）
    fetch POST 到 `${GAMES_API_BASE}/__files`，与 IndexedDB 缓存并行。
- **云函数 GET/POST 单条分支加 try/catch**：失败返回 200 + `{success:false}`，不再刷 500。
- **`cloudbaseStorage.ts` 补 `cloudPath`**：`fileManifest.push({fileName, cloudFileID, cloudPath})`，保留云存储兜底。
- **顺手修复预存类型错误**：`savePublishedGame` 中 `...game, players: game.players ?? 0`
  因 `game` 是 Omit 类型而报 TS ERROR —— 改为字面量 `players:0, status:'available'`。

### 关键经验
- 游戏文件跨浏览器共享：**必须走 DB 集合直读**，绝不能完全依赖云存储（匿名 `getTempFileURL` 不可达）。
  `dist/static/game-files/` 静态目录方案也不可靠（静态托管 rewrite 吞非 index.html 路径，且不同 origin 无共享缓存）。
- `game_files` 集合读取发生在**云函数服务端**（admin SDK），不依赖集合的匿名读权限配置。

### 部署
- 云函数 `tcb fn deploy gamesApi --force` 成功；前端 `tcb hosting deploy ./dist/static /` 成功。
- ⚠️ **用户需手动操作**：在浏览器重新发布 `game-1786321687027`（以及任何之前上传但只走云存储的游戏），
  才能让文件内容写入 `game_files` 集合。重新发布后跨浏览器即可加载。
