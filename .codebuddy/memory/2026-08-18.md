## 排查「任务奖励发放后钱包数额没变」

### 结论
**服务端奖励发放正常**，无 bug。证据（`.data/memory-db.json`）：
- `game_wallets` 中 `game-1786947440459::test-003` 余额 `{computingPower:0, gameCoins:400, diamonds:0}`
- 4 条 `quest_reward` 交易（+100 gameCoins each，时间 14:20/15:23/16:04/16:12），4 个 merged 任务 × 100 = 400 完全匹配

### 为什么用户「钱包数额没变」
**两套独立钱包系统**：
1. **平台钱包**：`WalletSkill.getBalance`（key=`allinone_wallets` localStorage + `users` 集合，`{gameCoins, instantVouchers, algorithmVouchers}`）——平台界面（Marketplace/PlatformGameStore/个人中心）显示的都是这个
2. **游戏内钱包**：`game_wallets`（`{computingPower, gameCoins, diamonds}`，key=`{gameId}::{userId}`）——**任务报酬发到这里**（quests.ts merge ②段 / 云函数对齐）

任务报酬设计上就发 game_wallets（quest.ts 注释「复用 game_wallets 多币种」）。平台界面不读 game_wallets → 不显示 → 用户看平台钱包当然「没变」。

### 额外发现
- 本地 `src/server/routes/games.ts` **没有 `__wallet` 隧道路由**（0 匹配）→ dev 下游戏内钱包也无法通过平台隧道查询
- 游戏内 SDK（`publishing-center/standard-sdk/apis/WalletAPI.ts`）走 `getFeatureApiBase('wallet')`（dev 分支 `/api/wallet` 是坏的，memory 已记）→ 游戏内也查不到

### 待用户决策的改进方向
- A：加本地 `__wallet` 隧道（GET balance）+ 任务广场/个人中心展示「我的任务报酬」（读 game_wallets）→ 让报酬可见
- B：任务 merge 时把 gameCoins 也写入平台钱包（WalletSkill/users）→ 平台钱包直接增加（涉及 CloudBase users 写入问题）
- C：保持现状（报酬仅游戏内钱包，游戏内 SDK 消费）

## 任务广场白屏修复（同日，用户实测报错）
- **现象**：`QuestPlaza.tsx:205 Uncaught ReferenceError: myRewards is not defined` → 任务广场白屏
- **根因**：给 QuestPlaza 加「我的任务报酬」卡片的 4 处修改（import / state 声明 / useEffect / JSX 卡片）**并行 replace 出现竞态**——import 与 state 两处未落到文件，但 useEffect 与 JSX 生效 → JSX 引用未声明的 `myRewards`/`Wallet`/`gameWalletService` → 编译运行时报错
- **教训（重要）**：⚠️ **同一文件的多个不连续 replace 必须串行（一次一个）**，并行执行会有竞态导致部分修改丢失（工具虽返回 success）
- **修复**：串行补齐 import（lucide `Wallet` + `gameWalletService`/`MyRewards`）与 `const [myRewards, setMyRewards] = useState<MyRewards|null>(null)`；lint 0 error + 读文件确认四部分齐全
- 用户刷新页面（硬刷新）即恢复；dist 产物完整无需重 build

## 任务报酬组件重构（同日，用户反馈三点：按用户隔离 / 隐私 / 移到导航栏）

### ① 用户隔离修复（根因：token 缓存不随用户切换）
- **根因**：`authTokenService.getToken()` 用模块级 `cachedToken` 缓存，**未绑定 userId**——切换用户后仍返回旧用户 JWT → 后端 `resolveUserId` 解析出同一 userId → `my-rewards` 所有用户显示一样
- **修复**：`getToken`/`getCachedToken` 增加 `cachedTokenUserId`，仅当 `cachedTokenUserId === getCurrentUserId()` 时复用缓存，否则按当前 userId 重新签发；`clearToken` 同步重置
