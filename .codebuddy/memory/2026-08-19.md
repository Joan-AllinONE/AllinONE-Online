## 修复：启用内容 SOP 后点击游玩白屏（GamePlay Hooks 违规）

### 现象
发布成功，点游玩后白屏。控制台：`GamePlay.tsx:687 Rendered more hooks than during the previous render`，diff 显示 41→42（多出 `useEffect`）。

### 根因
`GamePlay.tsx` 第 687 行「内容工坊加载内容凭证」的 `useEffect` 被放在**条件早退之后**（`if (isLoading) return` / `if (!game) return`）。首渲染提前 return 只跑 41 个 Hook，游戏数据加载后走到该 useEffect → 42 个 → React 抛错卸载整树 → 白屏。该 Hook 属于内容 SOP 功能（最近新增），故启用 SOP 后才触发。

### 修复
把该 `useEffect`（含 `setContentVouchers([])` 守卫）移到 `if (isLoading)` 之前、与其它 Hook 同区。Hook 自带 `!game?.contentSop?.enabled` 守卫，提前执行安全。

### ⚠️ 教训
- **React 组件内任何 Hook 都必须在所有条件 return 之前**。新增 Hook 时先确认早退位置。
- 验证：`search_content '^\s*(useEffect|useMemo|useCallback|useRef|useState|useLayoutEffect)\('` 可快速列出全部 Hook 检查位置。

## 功能：内容工坊凭证上架到商店「道具凭证」tab

### 需求
内容工坊铸造的凭证（category='content'）只在游戏内可用，商店「道具凭证」tab 无此商品。要求与道具工坊铸造的凭证一样上架。

### 方案（mintContentVouchers 增加 listOnStore 参数）
- **创建/复用内容模板**：`ItemVoucherTemplate`（itemType='content'，gameEffect.schemaName='content'，attributes.contentId 唯一标识去重），定价=单价 price（ACOIN，acceptVoucher）。模板经 saveTemplates→voucher_templates 后端同步，商店 getItemTemplates 直接显示，**purchaseItemVoucher 无需改**（库存匹配 customData.itemTemplateId）
- **凭证进平台池**作商店库存（customData.itemTemplateId=模板id）→ 购买后转移给买家，凭证带完整 contentPack → GamePlay 可用
- **赠创作者 1 张自用**（`（自用）` 名 + itemTemplateId:undefined），保持「铸造完即可在游戏里用」
- ContentWorkshop 加「上架到商店」checkbox（默认开）；未开时保持原行为（全发给自己）

### 改动文件
`voucherItemService.ts`（mintContentVouchers）、`ContentWorkshop.tsx`（listOnStore state+UI）、`GameStore.tsx`（ITEM_TYPE_LABEL 加 content='内容凭证'；卡片 schemaName==='content' 显示「内容凭证 1 张=1 次会话」）、`ItemVoucherManager.tsx`（getItemTemplates 过滤 `schemaName!=='content'`，防止管理页误铸造成道具凭证）

### 踩坑
- `createItemTemplate` 的 Omit 只去掉 id/createdAt/updatedAt/mintedCount，**isActive 必填**，漏传报 TS 2345
- 赠送分支 recipientName 可能 undefined，需 `|| PLATFORM_POOL_NAME`

## 功能：内容模板上架 A币凭证系统「道具凭证」tab（可持续铸造）

### 需求
内容凭证模板也要出现在 A币凭证系统「道具凭证」tab（`/voucher-system?tab=item-vouchers`，ItemVoucherManager），并像道具模板一样可反复铸造持续运营。

### 实现
- **manifest 持久化**：`mintContentVouchers` 创建模板时 `attributes.manifest`（内容包清单）+ `attributes.assetBase`；复用旧模板时若缺 manifest 自动补齐（兼容旧模板）
- **新增 `mintContentVouchersFromTemplate(templateId, count)`**：从模板读 contentId/type/slot/assetBase/price，manifest 优先 attributes.manifest，fallback 平台池已铸造凭证复制 contentPack（旧模板无 manifest 且库存清零时提示去内容工坊先铸造）；内部调 mintContentVouchers({listOnStore:true}) 复用模板+凭证进平台池
- **ItemVoucherManager**：恢复显示内容模板（移除之前的 schemaName!=='content' 过滤）；`handleMint` 对内容模板分支走 mintContentVouchersFromTemplate；铸造弹窗/card 加内容凭证标识（`内容: contentId`）
- **投票治理（用户决策修正）**：内容凭证与道具凭证一致纳入社区投票——voteMode 下内容模板可发起 MINT_ITEM 提案；`executeApprovedProposal` MINT_ITEM 分支按模板类型分流（schemaName==='content' → mintContentVouchersFromTemplate）；GameProposalCreateModal 模板下拉标注「内容·」、描述文案区分内容/道具

### 踩坑
- 内容模板铸造必须带 manifest（contentPack），不能走 mintItemVouchers（会铸成 category='item' 的错误凭证）
