# 2026-08-26

## 任务广场/任务发布关闭删除按钮「看不到」修复

### 根因
按钮之前只在 `QuestDetailModal` Header 里、纯图标（Power/Trash2）、且 `isOwner`（quest.createdBy === getCurrentUserId()）才显示，非常隐蔽；用户浏览别人的任务时完全不显示。

### 改进（3 处）
1. **QuestCard 卡片直接加关闭/删除按钮**（创建者可见，`e.stopPropagation()` 不触发打开详情；删除二次确认 3s 自动还原）；QuestCard 新增 `onChanged?` prop
2. **QuestDetailModal Header 按钮加文字**（`关闭` / `删除` / `确认删除?`，带边框色块更醒目）
3. **QuestPlaza 加「我发布的」筛选 tab**（`mineOnly` state，`q.createdBy === getCurrentUserId()` 过滤），创建者快速找到自己的任务

### 注意
- 按钮仅任务创建者可见（`quest.createdBy === getCurrentUserId()`）；`getCurrentUserId()` 从 `localStorage allinone_user` 读 uid/id
- 删除仍要求先 closed（卡片/弹窗按钮 disabled 提示「先关闭再删除」）

任务广场/任务发布没有关闭和删除任务的功能，需加入。

### 权限模型
- **关闭**：仅任务创建者（createdBy === 当前用户），open/review 状态可关
- **删除**：仅任务创建者，且**必须先 closed 再删**（防止误删进行中/有提交任务）；删除时级联清理 quest_claims / quest_submissions

### 改动（双后端同步 + 前端）
1. `src/server/routes/quests.ts`（本地）：
   - `POST /:id/close` 增加权限校验（`quest.createdBy !== userId → 403`）
   - 新增 `DELETE /:id`（仅创建者 + status==='closed'；级联删 claims/submissions）
2. `cloudfunctions/gamesApi/index.js`（云函数）：
   - close 同样加 403 权限校验
   - 新增 `DELETE` 单段路由（删 quest 文档 + where({taskId}) 批量删 claims/submissions）；总路由 `Access-Control-Allow-Methods` 已含 DELETE，无需改
3. `src/server/memoryDatabase.ts`：新增 `deleteQuest` / `deleteQuestClaimsByTask` / `deleteQuestSubmissionsByTask`
4. `src/services/questService.ts`：新增 `deleteQuest(taskId)`（DELETE 请求，带 token）
5. `src/components/quest/QuestDetailModal.tsx`：Header 加创建者专属操作按钮——
   - `Power` 图标=关闭（disabled 当 closed/merged），`Trash2`=删除（disabled 当非 closed；首次点击变红色确认态，再次点击执行）
   - 用 `getCurrentUserId()` 与 `quest.createdBy` 判断 `isOwner`；操作结果显示在 header 下方
