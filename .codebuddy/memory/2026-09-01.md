# 2026-09-01

## dev 环境已发布游戏「删了又回来」根因与修复

### 根因
用户 dev 下清了浏览器 Local Storage + IndexedDB，刷新后游戏列表仍出现。
两层原因：
1. 前端：`getPublishedGames()` 全程走本地缓存（_publishedGamesCache/localStorage/IndexedDB），`saveGamesToCache` 还会把后端拉到的数据写回 IndexedDB → 删除后又被补回。
2. 后端：用户之前启动 `server.js` 未设 `USE_MEMORY_DB=true`，连的是 PostgreSQL（`DATABASE_URL`）。浏览器缓存清了，后端 DB 里数据还在，刷新即拉回。**若 DATABASE_URL 指向生产 PG，则 dev 直接读写生产库 = 用户担心的「dev 污染生产」真正通道**。

### 已实施改动（方案 2：dev 跳过本地缓存 + 物理隔离）
1. `src/services/publishedGameService.ts`:
   - `getPublishedGames()`：dev 下跳过一切本地缓存，直接以后端为权威源，首次触发后台刷新。
   - `saveGamesToCache()`：dev 下只更新内存变量，绝不写 localStorage/IndexedDB（斩断污染循环）。
   - `savePublishedGame()` SOP 块：dev 下只走本地后端 API，绝不写云存储。
   - 以上全部用 `import.meta.env.DEV` 门控，prod 逻辑不变。
2. `package.json`：`dev:server` 改为 `cross-env USE_MEMORY_DB=true node server.js`（新增 devDependency `cross-env`），`start`/`build` 不动 → 生产部署仍按原环境变量决策。
3. 删除 `.data/memory-db.json`，停旧 server，重启 `pnpm dev` → 后端日志确认 `dbMode: 内存数据库`，`GET /api/v1/games` 返回 0 条，dev 数据已清空且与线上物理隔离。

### 用户关键约束（务必遵守）
- 用户明确要求：**dev 测试内容绝不能污染生产环境**。之前发生过 dev 数据通过云上传到线上。
- 隔离铁律补充：dev（`localhost` 或 `VITE_APP_ENV=development`）一律不写线上共享存储（云函数/云存储/生产 PG）。`GAMES_API_BASE` 在 dev 是相对路径 → 本地 server.js，本身物理隔离线上绝对 URL。
- 彻底清 dev 数据步骤：停 server → 删 `.data/memory-db.json` → `pnpm dev` → 刷新（无需手动清浏览器缓存，前端改动已跳过本地缓存）。

### 注意
- dev 前端虽跳过本地缓存，但游戏文件类 SW/IndexedDB 离线兜底（另一套）未动，播放已发布游戏不受影响。
- GameCenter 内置硬编码游戏（newday/puzzle/memory/snake…）非发布数据，永远显示，非缓存问题。
- 临时日志 `dev_stdout.log`/`dev_stderr.log` 被 dev 进程占用未能删除，无害。
