# 2026-09-02

## dev 发布游戏封面/简介刷新后丢失 — 根因与修复

### 现象
用户 dev 下发布游戏，上传的封面图和简介「一开始在游戏中心列表有，刷新后没了」（游戏名还在）。

### 根因
`server.js` 全局限流 `generalLimiter` 挂在 `app.use('/api/')`（windowMs=15min, max=300，按 localhost 单 IP 共享额度）。
dev 下前端 + iframe 子资源（每个游戏文件一个请求）+ 列表轮询迅速打满 300 次窗口 →
- 发布 POST `/api/v1/games` 被 429 → 封面/简介（与 name 同一条 POST）静默失败 → 后端落库残缺；
- 刷新时 GET `/api/v1/games` 也被 429 → 拿不到数据 → 封面/简介全丢。
（name 残留是因更早某次 POST 在限流窗口外成功）

### 已实施改动
`server.js` 的 `generalLimiter.skip` 增加 `process.env.USE_MEMORY_DB === 'true'`：
dev 豁免全部 `/api/` 限流；prod（无 USE_MEMORY_DB）不受影响。

### 验证
node 脚本 POST `/api/v1/games/dev-token` 拿 JWT → POST 带 coverImage/summary（200）→
GET 返回 hasCover=true, hasSummary=true。修复前 GET 返回 429。

### 注意
- dev-token 正确路径 `/api/v1/games/dev-token`（gamesPublicRouter 公开路由，无 auth）；
  `/api/dev-token`（无 v1）会落全局 authMiddleware 返回 401，属路径错误非 bug。
- 发布路由 POST `/api/v1/games` 在 gamesAuthRouter（需 JWT）；列表 GET / 在 gamesPublicRouter（公开）。

## 清理残缺游戏
用户「控制台应用清空存储」清的是浏览器/云侧，清不掉 dev 本地后端内存库（.data/memory-db.json）。
用脚本（dev-token → DELETE /api/v1/games/:id）删掉 2 条残缺记录（game-1788307194450 / game-1788309190416），
磁盘确认 publishedGames=0、gameFiles=0。这些记录 name 错存成 entryPoint、无封面、无文件，故玩不了。

## 新增：dev 测试数据一键清理工具（用户需求）

### 文件
1. `scripts/dev-clean.cjs` — 后端清理（Node）
2. `scripts/dev-clean-browser.js` — 浏览器侧清理（控制台粘贴执行）
3. `package.json` 新增 scripts：
   - `dev:clean` → `cross-env USE_MEMORY_DB=true node scripts/dev-clean.cjs`（停→清→重启完整 dev）
   - `dev:clean:only` → 同上 + `--no-restart`（只清不重启）

### 后端脚本核心逻辑
**顺序铁律：必须先停 server 再删文件**。因为 server.js gracefulShutdown（348-353 行）退出时会
`memoryDB.flush()` 落盘，若先删文件再停 server，退出时旧数据会被写回磁盘，白删。
流程：安全门控 → 按端口(3000/3001)停进程 → sleep 2s → 删 .data/memory-db.json（及 .data 下其他文件）→ 重启 pnpm dev。

### 安全设计（防污染生产，用户强约束）
- 强制门控：必须 `USE_MEMORY_DB=true` 或 `CLOUDSTUDIO=true` 才执行，否则 exit 1 并提示
  （避免 PostgreSQL 模式下误删本地文件却以为清了库）。
- 脚本只删本地 `.data/memory-db.json`，不连接/请求/修改任何远程、云、生产资源。
- 浏览器脚本只清当前 origin 存储，且非 localhost 直接拒绝执行。

### 浏览器脚本清理范围
localStorage（保留 KEEP_KEYS=['theme']）、所有 IndexedDB（含 AllinONE_GameFiles / writeQueue，
兜底库名兼容旧浏览器）、Cache Storage、注销 Service Worker，完成后自动 reload。

### 踩坑
- Windows 下 `execSync('timeout /t 2 /nobreak >nul')` 报「Input redirection is not supported」→
  改用 Node 原生 `Atomics.wait` 阻塞 sleep（带忙等降级）。
- `cross-env` 未全局安装，PowerShell 里直接敲 `cross-env ...` 报 command not found →
  必须通过 `pnpm dev:clean` 运行（pnpm 会注入 node_modules/.bin 到 PATH）。

### 验证结果
- 不带 USE_MEMORY_DB 运行 → exit 1 拒绝执行（门控生效）
- `pnpm dev:clean:only` → 停进程、memory-db.json 删除、后端 DOWN
- `pnpm dev:clean` → 完整重启后 `GET /api/v1/games` 返回 games=0（空库），vite 3001 已启动

### 注意
- dev 重启含 tsc 编译（build:server），需等数秒后端才可用。
- 浏览器侧通常刷新即可（dev 下 publishedGameService 已跳过本地缓存）；
  清浏览器缓存用于清除游戏文件缓存、凭证、钱包等其余测试数据。
- 临时日志 dev_stdout.log/dev_stderr.log 被 dev 进程占用，停 dev 后可删。

## 封面上传后游戏中心不显示（排查中，已加诊断）

### 现象
用户发布时上传了封面，后端记录 `game-1788311834781` 存在但 `cover=false / summary=false`。
日志显示 POST 成功落库（`后端返回 1 条已发布游戏记录`），说明**前端传的 coverImage 为空**，不是后端写入失败。

### 已排除的可能
- ❌ 限流 429：已修（dev 豁免），且记录成功落库。
- ❌ dev-token 400：日志里大量 `dev-token 400` 来自 **activityService（传 event.userId，可能为空）**
  等埋点调用，非发布链路。发布链路用 `getBackendSopToken()` 传固定 'platform-admin'。
  node 直连 3000 与经 vite 3001 测 dev-token 均返回 200。
- ❌ SW 拦截丢 body：dev 下 `getApiBaseUrl()` 返回 '' → handleRequest 走 `fetch(req)` 同源直连
  （gameFileServiceWorker-v14.js:662），POST body 保留。仅 GET 游戏文件走三级回退。
- ❌ vite 代理丢 body：proxy 配置仅为 `/api` → localhost:3000 + changeOrigin，无 rewrite。
- ❌ body 超限：coverImage 压缩到 800px 宽 JPEG，后端 express.json limit=150mb。
- ✅ 后端能存封面：node 脚本 POST 带 coverImage → 200，GET 返回 hasCover=true（已验证）。
- ✅ 传递链完整：PublishingCenter(819-820 publishConfig.summary/coverImage) →
  pipeline(801-802 config.summary/coverImage) → publishedGame → savePublishedGame → upsertGameToBackend。
  handlePublish 依赖数组含 summary/coverImage，state 绑定正确（handleCoverChange 393-421）。
- 无自动重置 coverImage 的逻辑（仅「移除封面」按钮 setCoverImage('')，1324 行）。

### 已实施改动（让静默失败可见 + 修可见 bug）
1. `publishedGameService.ts` `upsertGameToBackend()`：非 2xx 时打印 HTTP 状态码 + 响应体 + 
   hasCover/hasSummary，失败不再静默（此前 `.catch(()=>{})` 全吞）。
2. `publishedGameService.ts` `savePublishedGame()`：dev 下打印
   `发布落库: <id> | coverImage长度=N | summary长度=N`；写入失败时明确告警「刷新后封面/简介会丢失」。
3. `PublishingCenter.tsx` handlePublish：修复游戏名回退带扩展名
   （`超级玛丽改造5.html` → `超级玛丽改造5`），`.replace(/\.(zip|html?|htm)$/i,'')`。

### ✅ 根因已确证（2026-09-02 修复完成）
**`src/pages/PublishingCenter.tsx` 的 `handlePublishComplete` 在管线发布完成后又调了一次
`savePublishedGame`，构造的对象只列举了 hostingType/baseUrl/entryPoint 等字段，
唯独没有 `coverImage` / `summary`** → 第二次 upsert 把管线刚写入的封面、简介**整体覆盖成空**。
（日志里 `publishedGameService.ts:840 游戏已保存到 CloudBase + 缓存` 出现两次，就是这两次调用）

机制验证（node 脚本模拟三次 POST 同一 id）：
```
① 管线发布（带封面）      → hasCover = true  | hasSummary = true
② 二次保存【不含封面】    → hasCover = false | hasSummary = false   ← 修复前行为
③ 二次保存【含封面/简介】 → hasCover = true  | hasSummary = true   ← 修复后行为
```
注意 `...(existing || {})` 展开在最前，理论上能带出封面；但 existing 为 null（缓存未就绪/时序竞态）
时展开为空对象 → 封面必丢。故修复需双保险。

### 本轮修复清单（均已验证）
1. `src/pages/PublishingCenter.tsx` handlePublishComplete：
   - existing 为 null 时**跳过二次保存**（只读到残缺对象时不覆盖管线数据），仅弹成功提示；
   - 显式带上 `coverImage: existing.coverImage` / `summary: existing.summary`（防字段列表再次遗漏）。
2. `src/publishing-center/ui/PublishingCenter.tsx` handlePublish：游戏名回退去掉扩展名
   （`超级玛丽改造5.html` → `超级玛丽改造5`），`.replace(/\.(zip|html?|htm)$/i,'')`。
3. `src/services/apiBase.ts` `getFeatureApiBase()` dev 分支：
   **历史 bug** — 曾返回 `/api/${feature}`（缺 `/v1`），而本地后端路由全在 `/api/v1/` 下。
   现按两类解析：本地已有隧道路由的（wallet/quests/content）→ `/api/v1/games/__<feature>`；
   其余顶层路由（analytics/game-developers 等）→ `/api/v1/<feature>`。
   实测：`/api/game-developers` 返回 HTML（导致 `JSON.parse: Unexpected token '<'`）→
   `/api/v1/game-developers` 返回 200 JSON；`/api/analytics/events` 404 → `/api/v1/analytics/events` 200；
   `/api/v1/games/__wallet/balance` 200 JSON。prod 分支（isCloudHosting）不变。
4. `publishedGameService.ts`：发布写入后端失败不再静默（打印状态码/响应体 + hasCover/hasSummary），
   dev 下打印 `发布落库 | coverImage长度=N | summary长度=N`。
