# 2026-09-06 工作日志

## 游戏审核机制落地（本地运行，未部署）

### 需求
独立于发布流程的游戏审核：仅管理员可操作；提交→待审核→未过审不公开上架；四项审核条件；通过/驳回/需修改+原因；记录完整可追溯；支持复审/下架。

### 实现（8 个文件）
- 新增 `src/server/routes/gameReview.ts`：`/api/v1/games/__review` 隧道（挂 gamesPublicRouter 之前，内部自行解析 JWT）。
  - `POST /admin-login`：独立管理员登录（env `REVIEW_ADMIN_USER`/`REVIEW_ADMIN_PASS`，默认 admin/admin123），签发 `role=admin` JWT
  - `GET /list`（admin，?status= 过滤）、`GET /records/:gameId`（admin，时间倒序）
  - `POST /submit`（发布者/admin，置 pending + 跑自动预检：信息完整性/文件健康度/恶意代码特征扫描 eval(atob、挖矿、cookie 外传等，仅警告不拦截）
  - `POST /decide`（admin；approve 强制四项 checklist 全过；reject/changes_required 必填 reason）
  - `POST /takedown`（admin，必填 reason）
- 修改 `src/server/routes/games.ts`：
  - `GET /` 公开列表过滤：仅 `reviewStatus==='approved'` 或缺省（旧数据兼容）；admin 带 `?all=1` 可看全部
  - `GET /:id` 非 approved 仅 admin / publisherId 本人可读，否则 404（含 GamePlay 直链）
  - `POST /` + `PATCH /` 用 `stripReviewFields` 剥离审核字段；**新建游戏默认 `reviewStatus='pending'`**（防 submit 失败绕过审核）；已存在游戏保留审核字段（防 upsert 洗白 pending）
- 修改 `server.js`：挂载 `__review`（__content 之后、gamesPublicRouter 之前）
- 新增 `src/services/gameReviewService.ts`：前端 API 封装；`REVIEW_CHECKLIST_TEMPLATE` 四项与后端双维护；admin 会话存 sessionStorage（`allinone_review_admin_session`）；submit/decide/takedown 成功后 `refreshGamesCache()`
- 修改 `publishedGameService.ts`：`PublishedGame` 加 `reviewStatus/reviewRecords/submittedAt/reviewedAt/reviewedBy`
- 修改 `PublishingPipeline.ts`：stepPublish 保存后自动 `submitGameForReview`；stepActivate 文案改为"已进入待审核状态"
- 修改 `PublishingCenter.tsx`：toast 改"游戏已提交审核！"
- 新增 `src/pages/GameReviewAdmin.tsx`（`/game-review`）：登录卡片 + 状态统计（5 状态卡片可点过滤）+ 队列列表 + 审核 Modal（自动预检展示 + 四项 checklist 通过/不通过+单项备注 + 原因/备注 + 通过/需修改/驳回/下架按钮 + 审核记录时间线）
- `App.tsx` 加路由；`GameBase.tsx` 管理员菜单加"🛡️ 游戏审核"入口；`GameCenter.tsx` 用 `isGamePubliclyVisible` 过滤；`GamePlay.tsx` 在 `!game` 早退之后加 reviewStatus 渲染守卫（非 hook，安全）

### 状态机
submit→pending→approved/rejected/changes_required；rejected/changes_required 重新发布→pending；approved→takedown→removed→admin 重新 approve→approved；缺省（旧数据）=approved 兼容。
