## 跨游戏适配「不可用」修复（游戏通道不存在 + extension_vouchers 404）

- 现象：GameStore「来自其他游戏的道具」点「适配到本游戏」→ 控制台 `[ProtocolEngine] 游戏通道不存在: game-xxx` + `POST /api/v1/games/extension_vouchers 404`×3，界面无任何反馈。
- 根因三层：
  1. **商店页永远没有 protocol channel**（GamePlay unmount 即 `releaseChannel`；跨标签页内存不共享）→ `redeemItemVoucherBySchema` 的 sendToGame 必失败返回「游戏通道不可用」。这是既定 fallback，**源凭证未被消耗**（`redeemVoucher` 在 sendToGame 成功之后执行）——跳转游戏页重走兑换是通的。
  2. **【UX 致命伤】**失败反馈（error 文案 + 「打开游戏并自动下发道具」Link）**只在「我的道具凭证」列表渲染**，跨游戏区块没有 → 用户点完毫无反应 = 感觉功能坏了。
  3. `ExtensionVoucher.save` 裸调 `saveToBackend`（唯一没有 `isCloudSyncEnabled` 守卫的集合，违反「dev 不写云」）→ 本地 server（`server.js`+`games.ts`，**无任何集合同步路由**）返回 404；其他集合都有守卫故不刷屏。
- 修复（3 文件）：①`ExtensionVoucher.ts` save() 加 `isCloudSyncEnabled()` 守卫 + 新增 `remove(id)` ②`voucherItemService.ts` BySchema 失败分支清掉本轮创建的 extension_vouchers（`createdVoucherIds`，跨游戏 2 条/同游戏 1 条）防垃圾累积 ③`GameStore.tsx` 跨游戏区块行内渲染 error + 「打开游戏并自动适配下发」Link（`/game/{gameId}?itemVoucher={id}`），文案改为「游戏通道不可用（商店页无法直接下发）…」。
- **铁律**：跨游戏道具下发的唯一可行路径 = 商店页引导跳转 `/game/{gameId}?itemVoucher=<凭证id>` → GamePlay 轮询通道就绪 → `redeemItemVoucher`→`redeemItemVoucherBySchema`→adaptForGame→sendToGame 成功→`redeemVoucher`。**商店页直接兑换 schema 道具永远不可能成功**（无通道），不要再把兑换做在商店页。
