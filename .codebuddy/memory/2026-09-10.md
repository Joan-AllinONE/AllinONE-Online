## 「审核后游戏显示维护中无法进入」修复【已完成，前端已部署】

- 根因链：发布元数据 POST / 413（云函数 HTTP 访问服务请求体上限，拼豆 demo entryHtmlContent 131KB + coverImage base64）→ **整份元数据被拒** → 只有 cloudFileManifest 小 PATCH 成功 → 游戏文档残缺（无 name/status/hostingType/entryPoint）→ 游戏中心 status 缺失 → `statusText[undefined]` → 「维护中」锁死入口；submit 也因文档未就绪 404。
- 修复（前端，已 build + `tcb hosting deploy` 上线，新 bundle index-hcsCUC1G.js）：
  1. `upsertGameToBackend` 元数据瘦身：entryHtmlContent >60KB 剥离（文件加载走 manifest 链路）；coverImage >120KB canvas 压缩（max 边 640，JPEG 质量递降 0.85→0.3）
  2. GameCenter `status: pg.status || 'available'`（残缺文档不再锁死）
  3. `submitGameForReview` 404 自动延迟重试 ×3（manifest patch 并发创建文档的时序竞态）
- 文件加载回退链已确认（云函数 files 路由）：game_files → cloudFileManifest → **云函数端 admin SDK getTempFileURL 直接返回内容**（跨浏览器可用，<6MB）→ 所以 game_files 413 缺失不阻塞线上游玩，只要 manifest 在。
- 用户操作：强刷页面 → 重新发布游戏（新 gameId）→ 审核通过 → 正常；旧残缺文档（无名游戏 + game-1789026430706）建议审核后台下架清理。
- 遗留：413 上限未知确切值，超大游戏（多文件>数 MB）仍需分片/云存储直传方案；coverImage 压缩仅对 base64 data URL 生效。
