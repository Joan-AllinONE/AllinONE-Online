## 桌面宠物游戏白屏修复（发布入口选成 JS 文件）
用户反馈「桌面宠物」游戏加载白屏，iframe URL 为 `/api/v1/games/game-1789902673364/files/js/main.js`。

【根因】`GameCodeAnalyzer.analyzeFileStructure()` 把 HTML 入口和 JS 入口混在同一 `entryPoints` 数组按 ZIP 解压顺序 push；桌面宠物 ZIP 中 `js/main.js`（命名含 "main" 命中 JS 入口规则）排在 `index.html` 之前 → `entryPoints[0]='js/main.js'` → 发布管线（427/487/618/807 四处）用它当 entryPoint → iframe 加载 JS 文件白屏。SW 请求 main.js 本身 200 成功，链路其余部分正常。

【修复】
1. `src/publishing-center/ai/GameCodeAnalyzer.ts`：入口收集分离为 `htmlEntryPoints`/`codeEntryPoints`，最终列表按 `rankEntryPoint` 排序（根目录 index.html=0 > 深层 index.html=1 > 根目录其他 html=2 > 深层 html=3 > js/ts=4）。
2. `src/publishing-center/core/PublishingPipeline.ts`：新增 `pickEntryPoint(files, entryPoints)`（分析结果 HTML > files 根 index.html > files 任意 index.html > 任意 html > entryPoints[0] > 'index.html'），替换全部 4 处 `entryPoints[0]` 调用点。
3. `localPreviewService.buildLocalPreview` 已自带 HTML 优先（93-105 行），无需改。

【后续】用户需重新上传 ZIP 发布桌面宠物（旧记录 entryPoint=js/main.js 是坏数据）；本地 server 需重启（`__review/submit` 404 是旧进程，dist 产物 18:37 已含 submit 路由，server.js 200 行挂载正确）；发布后新游戏 reviewStatus=pending，GET /:id 404 是待审核可见性设计（仅发布者/管理员可见），需 admin 在 /game-review 过审后才能游玩。
