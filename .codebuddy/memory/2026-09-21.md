## GameQuest 数据型扩展四道墙修复（levels/赌石矿区任务合并后不可达）
需求：用户用 slot=levels 提交赌石新矿区任务，三种提交方式全被拦；即使合并成功玩家也无入口。

### 根因（4 层）
1. levels Schema `requiredKeys:['id','title']` 且强制数组 → 莫西沙矿区对象（无 title）被拦；asset 上传 json 不解析进 data
2. 审核通过 ≠ 合并（须再点 merge）
3. 合并数据带 `_submissionId`，不带 `?ext=` 打开=纯净原版被过滤
4. **致命 bug**：merge ①c 仅在 `assets.length||entryPoint||inject` 时写 questExtensions → 纯数据合并后无记录 → GamePlay 扩展菜单无条目、computeEffectiveGame 匹配不到 ext → 数据型扩展完全不可达（GamePlay 数据分支 `questExt&&!entryPoint` 早已存在，只是记录从未写入）

### 修复（已实施+已部署 2026-09-21）
- `src/types/quest.ts`：QuestSlotSchema 新增 `allowSingleObject?:boolean`；levels `requiredKeys:['id']`+`allowSingleObject:true`+hint 重写（说明 data 框只粘数据、asset json 不解析进 data）
- `validateQuestContent`：数组型 slot 在 allowSingleObject 时放行单对象
- `src/server/routes/quests.ts` + `cloudfunctions/gamesApi/index.js`（双维护对齐）：①merge 单对象分支补 `_submissionId` 戳（与数组一致受 ?ext= 隔离）；②①c 条件追加 `|| !dataIsEmpty` → 纯数据提交也写 questExtensions
- 云函数 Schema/校验 JS 副本同步改（index.js ~1263/~1407）
- 游戏文档 `AllinONE Online/赌石小游戏/allinone/任务开发说明.md` 第五/六节修正：data 框只粘 data 字段内容（单个矿区对象或数组），勿粘整个 ContentPack；审核通过后必须点「合并」；合并后从游戏页「扩展」菜单进入

### 用户重新提交格式（赌石矿区，现在唯一需满足）
data 框粘单个矿区对象或数组即可，每条必须含 `id`（name/price/green/cap/w 等按字段表），无需再加 title。
