## 平台数据中心线上白屏修复（✅ 已部署 2026-09-22）

【现象】/platform-data-center 白屏，控制台 `TypeError: u.map is not a function`（index-C01DEnW0.js:3980）。
【根因】云函数 `__analytics` 旧桩：任意 GET 一律返回 `{events:[...]}`（对象）→ 前端 `fetchAnalytics('by-game')` 拿到对象 → `setGames(gm||[])` 防不住非空对象 → `games.length===0` 为 false → `games.map` 渲染崩溃；且 POST 只认 `/track`，前端 tracker 实际发的 `/events` 全部 405，线上埋点从未落库。注意 `gm||[]`/`k||[]` 只防 null/undefined 不防对象——排错方法论：下载线上 bundle 定位崩溃行列（本地 dist 与线上 hash 不一致时必须拉线上包），再用 dev-token curl 复现响应形状。
【修复】①云函数 analytics handler 重写（cloudfunctions/gamesApi/index.js）：POST 接受 /events（/track 兼容）+确定性 `_id=ev_{type}_{ts}_{uid}` 覆盖写幂等；GET 拆 overview/trends/by-game/players 四端点（分页拉 `game_analytics` 全量+聚合，口径镜像本地 analyticsStore.ts，脏数据按 type+timestamp 过滤，需 JWT）；②`PlatformDataCenter.tsx` 全部 fetchAnalytics 返回值形状归一化（Array.isArray 守卫+players 默认字段补齐）；③新增 `src/components/ErrorBoundary.tsx` 包住 App.tsx `<Routes>`（渲染崩溃显示错误页而非全站白屏）。
【部署】`tcb fn deploy gamesApi --force` ✓ + vite build（新 bundle index-DLJP0mUP.js）+ `tcb hosting deploy ./dist/static /` ✓；线上验证 by-game=Object[]、overview/players 形状正确、首页引用新 bundle。
【注意】①game_analytics 现仅 1 条脏数据（type:'play' 被过滤），指标从 0 开始累积（旧前端埋点全丢），数据随新 bundle 使用逐渐出现；②vite build 约 1m15s，execute_command 10s 监视超时会杀进程——用 `Start-Process cmd '/c ... > log 2>&1'` 分离后台跑+轮询日志；③SW 版本无关此修复（v18 未动）。
