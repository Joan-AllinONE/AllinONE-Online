## 修复清单（按危害分级，全部已修复并验证）
### 致命（资金级）
- **B-1 cron/tick triggerId 随机**：settle 部分成功后死信重试用新 txId → 已执行的资金效果重复执行=双花。修复=确定性 triggerId（`tick:{contractId}:{schedule}:{bucket}`，deadline-check=1h 桶/settlement-weekly=7d/settlement-monthly=30d），配合 saga txId 幂等实现安全重试。本地+云函数双修。
- **B-2 escrow FIFO 无用途隔离**：TeamQuest bond（先锁）与奖池（后锁）混池 → splitPayout 先扣光 bond、refundAll 把奖池退给团长=资金完全错乱。修复=EscrowEntry.purpose + escrowLock/Release/Forfeit/RefundAll 全链 purpose 定向过滤；模板标注 purpose（bond/pool/payment）。
- **B-3 refundAll 按 params.currency 过滤**：TeamQuest 币种在 rewardPool.currency，params.currency=undefined → 查不到任何条目=退款退 0。修复=不按 currency 过滤（退全部 locked，purpose 可选定向）。
### 高危
- **B-4 tq-reach-quorum 漏 +1**（开团延迟）；**B-5 tq-join 缺 active 态**（maxMembers 失效）；**B-24b 状态表缺 signing→active**（TeamQuest 开团直达）
- **B-6 dispute 的 reason:'expr: event.reason'** payload 缺字段即 eval-error → invoke 端点 payload.reason 默认 '（未填写）'
- **B-7 限购缺失**：DSL 新增 countUser(arr,userId)/sumUser(arr,userId,field)；gb join 用 countUser<perUserLimit、gso 用 sumUser+amount<=perUserCap、tq join 用 countUser<1（一人一份）
- **B-8 RSV 锁定期形同虚设**：frozenAt=now+lockupMs 真冻结（此前只写 metadata.lockupUntil）
- **B-9 settlementCron 死参数**：gso-revenue-share 拆 weekly/monthly 双条款+when 守卫
- **B-10 A币退款字段名不匹配**（entry 存 voucherIds 数组，refundAll 读 voucherId 单数）
- **B-12 乐观锁未实现**：saveInstanceCAS（云函数 where version=expected）/putContractInstanceCAS（本地 Map version 校验）+ applyPlan conflict→409
