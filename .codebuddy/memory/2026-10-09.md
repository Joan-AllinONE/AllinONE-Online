## 平台金库三方分成收益不可见：账户 ID 分裂 + 流水无通道
- 用户反馈「平台管理的金库没有三方分成的收益数据」。根因是**第三处两本账**：
  1. **账户 ID 分裂**：platformTreasuryService 金库账户 = `system-platform`（前端 walletSkill 本地账本，市场佣金/回收等老流程）；gamecoins-split 平台份额 = `platform_treasury`（服务端 users 账本，gameDeveloper.ts PLATFORM_TREASURY_ID）。
  2. **流水无通道**：adjustPlatformBalance 只写 users._walletHistory（无独立 transactions 集合），且 listUsers 已剔除 _walletHistory → 服务端分账流水没有任何读取通道。
- getReport() 数据源实证：balance.gameCoins ← walletSkill('system-platform')；明细 ← localStorage（TREASURY_TX_KEY + marketplace treasury）；RevenueBreakdown 无分成类目 → platform_treasury 的分账收益完全不可见。
- 修复：
  1. memoryDatabase.listTransactions()——users._walletHistory 摊平导出（补 userId/id/txId 字段，按时间倒序；注意 _walletHistory 仅留 100 条/用户，非全量审计账本）
  2. games.ts `GET /transactions`（Bearer 必须、skip/limit、data.list 协议；同 /users 一样必须排在 GET /:id 前）
  3. platformTreasuryService：TreasurySource + RevenueBreakdown 加 `three_way_split`/`threeWaySplit`；getReport() 用 loadFromBackend('users'+'transactions') 聚合——balance.gameCoins = 本地 walletGC + 服务端 platform_treasury 余额；today/monthly income 并入 gcsplit_ 流水；breakdown.threeWaySplit = 分账累计
- 验证：tsc server 0 错误、前端仅历史 TS6133；端到端 3/3（两笔分账平台份额 1+2=3 → /transactions gcsplit_ sum=3 → /users platform_treasury.gameCoins=3）；冒烟 15/15。
- PlatformDataCenter 金库卡（treasuryGC=balance.gameCoins）自动包含服务端分账收益，无需改 UI。
- **遗留模式提示**：'system-platform'（前端金库）与 'platform_treasury'（服务端分账）仍是两个账户，报表靠前端聚合缝合；统一 ID 是更大手术（涉及云函数 __contract contractAdjust 等），暂不动。云函数侧 gamecoins-split 未实现（下次上线补时保持 platform_treasury ID + GET /users /transactions 双路由对齐）。

## 提案分成配置从未写入：initAutoExecuteListener 从未被调用（根因修复）
- 用户：道具凭证页发起带三方分成提案（creatorId=test-003），通过后面板仍「未配置」。怀疑 ID 出错。
- 服务端实证（GET /api/v1/game-developers）：accounts=1（game-game-1791412706377 超级玛丽改造6/publisher=test-001/gameCoinsRevenue=30），**rs=无**——若配置写到别的 gameId 会有第二个账户 → 排除「ID 写错账户」，真相是配置从未写入。
- 根因：**`voucherItemService.initAutoExecuteListener()` 定义了但全项目无调用**——提案 PASSED 后 checkAndFinalize dispatch 的 `proposal-auto-execute` 事件无人接听 → `applyRevenueSharingConfig` 从未执行。事件只在 finalize 时触发一次，刷新不重放 → 无补救机会。accountId 双前缀形态 `game-{gameId=game-xxx}` 全链路一致，非本因。
- 修复：①main.tsx 初始化链末尾 `.then` 动态 import 并调 `initAutoExecuteListener()`（根因）；②listener 内加**启动自愈**：扫描 `gameProposalService.getProposals()`（新增公开方法）中 status===PASSED && revenueSharing 的提案，逐个幂等重放 applyRevenueSharingConfig（补偿历史遗漏）。
- 用户恢复路径：刷新页面 → 启动自愈自动把 PASSED 提案的分成配置（creatorId=test-003）写入服务端 → 面板显示配置 → 后续购买按三方分账。也可在提案详情手动点「执行提案」。
- 教训：**定义了 handler 的方法必须确认有调用方**（叠加「事件只触发一次无重放」= 静默永久丢失）。
