# 豆趣工坊·像素熨斗 —— 任务开发说明

> 这份文档是接单玩家与玩家 AI 的**唯一依据**。
> 只公开接口与数据格式，不含任何游戏源码。

---

## 一、游戏简介

《豆趣工坊·像素熨斗》是一款拼豆（熔珠 / fuse bead）模拟器网页游戏。

**核心循环**：选图纸 → 夹豆摆放 → 熨烫定型 → 收藏 / 导出。

**玩法**：玩家在网格画布上点击或拖拽放置彩色圆豆来绘制图案。画满后点「🔥 熨烫定型」，豆子融合成平整成品（光面 / 毛巾 / 灯芯绒 / 磨砂四种效果），然后可收藏到「我的收藏」或导出 PNG。

**操作**：

| 操作 | 方式 |
|---|---|
| 填色 | 单击格子，或按住拖拽连续画 |
| 擦除 | 右键单击，或长按格子 |
| 取色 | 吸管工具点已放置的豆子 |
| 对称 | 水平 / 垂直 / 中心对称，镜像自动补豆 |
| 撤销重做 | Ctrl+Z / Ctrl+Y，或点按钮 |
| 清空 | 一键清空画布 |

**每张图纸支持三种模式**：

| 模式 | 说明 |
|---|---|
| 临摹 | 空白画布 + 半透明彩色提示，照着填 |
| 填充 | 一键铺满整张图纸（需消耗「一键填充券」道具） |
| 挑战 | 计时 + 进度条 + 闪烁提示格，按完成用时评 1~3 星 |

**网格尺寸**：13 / 21 / 29 / 43 / 59 五档可切换（任务提交的图纸允许 2~59 任意尺寸）。

## 二、你能为这个游戏做什么

| 任务类型 | 挂载点 slot | 交付物 | 难度 | 说明 |
|---|---|---|---|---|
| 新图纸（**推荐**） | `levels` | 一张拼豆图纸 JSON | ★ ~ ★★★★ | 出现在「社区图纸」区，支持临摹/填充/挑战 |
| 图纸包 | `levels` | 多张图纸（数组多条） | ★★ ~ ★★★★ | 一次提交一个主题系列，如「海洋生物 5 连」 |
| 配色包 | `items` | 一组主题颜色 | ★ | 载入后加入调色板，本次会话可用 |

## 三、通用约定

1. **交付物是内容包 ContentPack**，不是源码 diff。平台不做代码合并，只会把你提交的数据**追加**到游戏声明的挂载点上。
2. **assets 用相对路径**，如 `js/snowflake.js`。二进制文件用 base64 并加前缀 `__BINARY_BASE64__`。
3. **合并后才生效**：提交 → 审核通过 → 平台合并 → 带 `?ext=<submissionId>` 打开游戏时可见。未合并前本地自测看不到。
4. **原版与扩展隔离**：不带 `?ext=` 打开的是纯净原版，看不到任何社区内容——这是平台铁律，不是 bug。
5. **内容凭证按次消费**：内容工坊铸造的图纸 1 张凭证 = 1 次会话，刷新后失效，不会被写进存档。
6. **安全**：禁止提交访问网络、读写 localStorage、操作 DOM 的代码。平台会扫描拦截。
7. **版权**：禁止提交受版权保护的商业 IP 形象（动漫角色、品牌 Logo 等）。

## 四、游戏方开放的接口

### 4.1 图纸数据字段（`slot: levels`）

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `id` | 否 | string | 唯一标识，英文小写，如 `cat`；不填则用 title |
| `title` | **是** | string | 图纸名称，显示在卡片上 |
| `cols` | 否 | number | 网格宽度，2~59；不填按 layout 推算 |
| `rows` | 否 | number | 网格高度，2~59；不填按 layout 推算 |
| `legend` | 与 layout 搭配**必填** | object | 字符 → 颜色映射，如 `{".": null, "K": "#3a3a4a"}` |
| `layout` | 与 grid 二选一 | string[] | 字符串数组，每行一个字符串 |
| `grid` | 与 layout 二选一 | array[][] | 二维数组，元素为 `#rrggbb` 或 `null` |
| `script` | 否 | string | 脚本型图纸入口路径，如 `js/pattern.js` |
| `difficulty` | 否 | string | 自由文本，仅展示 |

**兜底规则（提交前请自检）**：

- `.` 与 legend 未登记的字符 = 空格（不放豆）
- 颜色只接受 `#rgb` / `#rrggbb`；`red`、`#GGG`、`javascript:...` 全部当空格丢弃
- 尺寸超出 2~59 自动钳制；声明大于实际则补空，小于则截断
- 至少 1 颗豆，全空图纸会被拒绝
- 可用调色板以外的颜色，游戏会自动注册为「扩展色」

### 4.2 完整示例

```json
{
  "id": "cat",
  "title": "小猫",
  "difficulty": "普通",
  "cols": 13,
  "rows": 13,
  "legend": { ".": null, "K": "#3a3a4a", "W": "#ffffff", "P": "#ffb3c6" },
  "layout": [
    ".............",
    "..K.......K..",
    "..KK.....KK..",
    "..KKKKKKKKK..",
    "..KWKKKKKWK..",
    "..KKKKPPPKK..",
    "..KKKKKKKKK..",
    "...KKKKKKK...",
    "....KKKKK....",
    "............."
  ]
}
```

### 4.3 脚本型图纸 API（`window.BeadLevel.build`）

| 成员 | 说明 |
|---|---|
| `api.COLS` / `api.ROWS` | 网格宽高（数字） |
| `api.setBead(c, r, hex)` | 在「列 c、行 r」放一颗豆；传 null 清空 |
| `api.rect(x0, y0, x1, y1, hex)` | 填充矩形区域 |
| `api.fill(hex)` | 整版填充 |
| `api.grid` | 二维数组引用，可直接读写 `api.grid[r][c]` |

```js
window.BeadLevel = {
  build: function (api) {
    var mid = Math.floor(api.COLS / 2);
    api.fill('#cfe8ff');
    for (var i = 0; i < api.COLS; i++) {
      api.setBead(i, mid, '#4a90d9');
      api.setBead(mid, i, '#4a90d9');
      api.setBead(i, i, '#4a90d9');
    }
  }
};
```

> API 就是边界：只暴露放豆与读网格的能力。内部渲染、存档、熨烫实现不属于公开接口，依赖它们的内容在未来的版本更新中可能失效。

### 4.4 配色包字段（`slot: items`）

```json
{ "colors": [ { "name": "奶油杏", "hex": "#ffd8b1" }, { "name": "雾霾蓝", "hex": "#8fb8de" } ] }
```

或直接给数组：`["#ffd8b1", "#8fb8de"]`。建议 4~12 色。

### 4.5 道具效果表（道具工坊用，非任务提交）

| 效果名 | 参数 | 说明 |
|---|---|---|
| `instant_fill` | `charges` | 授予 N 次一键填充次数 |
| `rainbow_fill` | — | 用调色板颜色铺满画布 |
| `clear_board` | — | 清空当前画布 |
| `instant_iron` | `effect` | 跳过覆盖判定直接熨烫（glossy/towel/corduroy/frosted） |
| `unlock_symmetry` | `mode` | 开启对称（none/h/v/center） |
| `unlock_color` | `hex`, `name` | 解锁一个自定义颜色 |
| `scatter_beads` | `count`, `hex` | 随机撒 N 颗豆 |
| `reveal_reference` | — | 显示半透明参考图 |

### 4.6 脚本沙箱签名

```
function (params) → { message: string }
```

可用变量：`game`（游戏实例，含 `setBead` 等公开方法）、`Math`、`JSON`、`console`。

**不可用**：`window` / `document` / `fetch` / `localStorage` / `eval` / `alert` 等，命中即拒绝注册。长度上限 4000 字符。

## 五、让 AI 帮你完成任务的提示词模板

把下面整段复制给 AI，替换最后一行的需求即可：

```
我要为《豆趣工坊·像素熨斗》创作一张拼豆图纸。

【输出格式】只输出 JSON，不要任何解释文字
{
  "id": "英文标识",
  "title": "图纸名称",
  "cols": 21,
  "rows": 21,
  "legend": { ".": null, "A": "#rrggbb", "B": "#rrggbb" },
  "layout": [ ".....", "..A..", ... ]
}

【硬性规则】
- '.' 表示空格；其余每个用到的字符都必须在 legend 里登记为 #rrggbb 颜色
- cols/rows 取值 2~59；layout 每一行长度必须完全相同（用 '.' 补齐）
- 至少要有 1 个非 '.' 的格子，否则图纸会被拒绝
- 颜色优先从内置 16 色里选：
  #e63946 #ff8c1a #ffd23f #4caf50 #36c2b4 #4cc9f0 #3a86ff #8b5cf6
  #ff8fb1 #a0714f #ffffff #3a3a4a #d9d9e3 #8a8a9a #ffe8c9 #ff5d8f
- 图案轮廓要清晰，色块尽量成片，避免孤立单像素和噪点
- 主体居中，四周留 1~2 格空白

【我要画的是】：（描述你的需求，例如「一只戴帽子的小猫，21×21，粉色系」）
```

## 六、提交格式与步骤

### 6.1 ContentPack 结构

```jsonc
{
  "type": "map",              // map（图纸）/ item（配色包）/ custom（纹理）
  "slot": "levels",           // 挂载点
  "name": "小猫",
  "description": "一张 13×13 的粉色小猫图纸",
  "data": { "id": "cat", "title": "小猫", "cols": 13, "rows": 13, "legend": {...}, "layout": [...] },
  "assets": [
    { "path": "js/pattern.js", "content": "window.BeadLevel = { build: function(api){ ... } };" },
    { "path": "bg.png", "content": "__BINARY_BASE64__..." }
  ],
  "entryPoint": "js/pattern.js"   // 仅脚本型需要
}
```

### 6.2 提交步骤

1. 在任务广场领取任务
2. 按上面的格式写好 `data`（脚本型还要写 `assets` 里的 `.js`）
3. 粘贴 JSON 提交；脚本型需上传文件并填 `entryPoint`
4. 等待审核（开发者直审 / 社区投票）
5. 合并通过后，游戏带 `?ext=<submissionId>` 打开即可在「社区图纸」区看到

### 6.3 提交前自检清单

- [ ] `title` 已填写
- [ ] `layout` 每一行长度完全一致（用 `.` 补齐）
- [ ] 所有用到的字符都在 `legend` 里登记过
- [ ] 所有颜色都是 `#rgb` 或 `#rrggbb`
- [ ] `cols` / `rows` 在 2~59 之间，且与 layout 实际尺寸一致
- [ ] 至少有 1 个非空格子
- [ ] 脚本型：`window.BeadLevel.build` 已定义，且未使用 fetch / localStorage / DOM
- [ ] 不含受版权保护的商业 IP 形象
- [ ] 单文件 ≤ 512KB

## 七、常见问题

**Q1：我提交了，为什么在游戏里看不到？**
A：内容必须**审核合并后**才生效，且需要带 `?ext=<submissionId>` 打开。不带参数打开的是纯净原版，看不到任何社区内容。

**Q2：为什么我图纸里的某些格子是空的？**
A：大概率是颜色值不合法（如写了 `red`、`#GGG`），或字符没在 `legend` 里登记。这两类都会被当空格处理。

**Q3：图纸尺寸和我写的不一样？**
A：游戏会把尺寸钳制在 2~59。若声明尺寸大于实际内容会自动补空，小于则截断。提交前请核对 `cols`/`rows` 与 `layout` 实际行宽一致。

**Q4：可以用调色板以外的颜色吗？**
A：可以。游戏会自动把新颜色注册为「扩展色」并加入调色板。但建议优先用内置 16 色，拼豆感更强。

**Q5：脚本型图纸不生效怎么办？**
A：确认 ①`window.BeadLevel.build` 已正确定义；②`entryPoint` 路径与 `assets[].path` 一致；③脚本里没有用 `fetch`、`localStorage`、DOM 操作——这些会被拦截导致脚本不执行。

**Q6：一次能提交多张图纸吗？**
A：可以。`data` 写成数组多条即可，平台会逐条展开追加到 `levels` 挂载点，每张各自带 `_submissionId`。

**Q7：内容工坊铸的凭证和任务广场提交有什么区别？**
A：任务广场合并 = **给游戏添东西**，永久发行、所有人可见；内容凭证 = **给自己造体验**，1 张凭证 1 次会话，刷新即失效，不会进存档。

**Q8：填充模式为什么用不了？**
A：「填充」是付费能力，需持有「一键填充券」道具。临摹和挑战模式不受限制，可直接使用。
