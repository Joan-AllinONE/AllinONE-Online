### 时序安全说明（2026-09-18 修复）

- 平台在游戏入口 HTML 的 `</head>` 前（游戏业务代码之前）注入 `AllinONE_ContentLoader` 骨架，文件分发层 / GamePlay inline / 云函数 / Service Worker 四条分发通道行为一致
- 本游戏代码段 B 采用 `window.AllinONE_ContentHandlers = { levels: handler }` 挂载表注册（loader `apply()` 时才读取该表，任何时机设置都有效，无时序依赖）+ `on()` 条件兜底，双保险幂等
- ⚠️ **修改代码段 B 的铁律**：切勿只写 `AllinONE_ContentLoader.on(...)` 条件守卫直接调用——若该脚本执行时 loader 尚未就绪，注册会被**静默跳过**（无任何报错），玩家使用内容凭证后矿区不出现（本游戏曾踩此坑，表现为事件日志「矿区内容已应用」正常打出但无 toast、矿区缺失）
- 已发布的游戏**无需重新发布**即自动享受平台侧 head 注入修复；用本文件夹的 `index.html` 重新发布可获得游戏侧双保险
- 验证方法：iframe 控制台执行 `window.AllinONE_ContentLoader._handlers.levels` 应为函数；使用内容凭证后应出现「🧩 内容凭证矿区…已临时加入」toast 且矿区页新增 🧩 玩家矿区

## 游戏奖励活动绑定（代码段 E 已集成）

游戏内已上报三个状态切换点（均只在平台 iframe 内、单次触发）：
- `ACHIEVEMENT_UNLOCK`：爵位晋升时（data: level, rank）
- `SCORE_MILESTONE`：总资产突破 10万 / 100万 / 1000万 时（data: assets, threshold）
- `GAME_COMPLETE`：集齐六档玉石图鉴时（data: dex, best）

运营者在「凭证系统 → 游戏绑定」为对应触发方式建绑定即可生效。**游戏内行为**：
- 爵位晋升/图鉴集齐天然低频，适合 ON_ACHIEVEMENT / ON_GAME_COMPLETE
- 资产里程碑适合作为成就型奖励

## 道具提取（ITEM_HARVEST）要点

- schemaName：`gushi-powerup`（平台 SchemaRegistry **已内置注册**，不再依赖道具工坊动态注册——刷新页面也不丢）；效果名限 `add_coins`（在 availableEffects 内）
- 产出点（2026-09-19 起）：**加工坊每件成品独立进入铸造栏**（碎石边角除外），估值 = 成品价值 × 0.85（500~50000 夹取，给买家留利润空间），玩家逐件「提取凭证」
- 凭证可交易：铸出的凭证 denomination=0、origin='gameplay'，可直接在市场上架挂牌；他人兑换回游戏按 bonus 折算玉币
- 三条铁律已实现：origin='gameplay' 标记 / 提取成功即删（防双花）/ harvestId 幂等 + 10s 超时兜底
- 平台风控：每用户每游戏每日提取 ≤10 次（DAILY_HARVEST_LIMIT）
- 平台模式懒检测：直接双击打开 HTML 不掉落
