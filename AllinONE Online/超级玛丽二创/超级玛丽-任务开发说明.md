# 超级玛丽 · 任务开发说明（玩家版 / AI 协作版）

> 本文档面向**领取《超级玛丽》开发任务的玩家**，以及玩家身边的 AI 助手。
> 游戏方（平台）只开放本文档列出的**接口与数据格式**，**不提供、不出售游戏源码**。
> 你不需要读懂或修改任何游戏内部代码——按本说明提交内容，审核通过后会自动合入游戏并生效。

---

## 1. 游戏简介

经典平台跳跃游戏：玩家控制角色在横向卷轴关卡中移动、跳跃、踩踏敌人、收集金币、顶破砖块，最终抵达旗杆过关。关卡由地面、砖块、问号金币块、管道、敌人（板栗仔）与道具等元素组成。

- 键盘：`←/→` 或 `A/D` 移动，`↑/空格/K` 跳跃（长按跳更高），`Shift/J` 加速跑，`P` 暂停，`Enter` 开始
- 过关条件：到达旗杆（`F`），游戏会自动在关卡末尾放置旗杆

## 2. 你能为这个游戏做什么

| 任务类型 | 难度 | 说明 | 对应的挂载点 slot |
|---|---|---|---|
| **关卡创作**（推荐） | ★☆☆ 零代码 | 用字符网格画一张新关卡 | `levels` |
| **修复 / 补回资源** | ★☆☆ 零代码 | 上传游戏缺失/损坏的文件 | `fix`（或任意 slot 纯文件补丁） |
| **道具创作** | ★★☆ 零代码~少代码 | 提交道具 JSON（预设效果或自定义效果） | `items` |
| **脚本构建关卡**（进阶） | ★★★ 需少量代码 | 用游戏方开放的构建接口写一段关卡脚本 | `levels`（`script` 字段） |

> 第 4 节会分别给出每种任务的**公开接口**。所有内容都是「数据 / 脚本」，不会触碰游戏源码。

## 3. 通用约定（先读）

1. **内容包（ContentPack）**：任务的产物是一个 JSON 内容包，包含 `data`（结构化的关卡/道具定义）、`assets`（可选的文件，如图片、脚本），提交后由平台审核、合并。
2. **assets 的 path 用游戏内相对路径**（如 `js/gun.js`），不含 `/api/...` 前缀；上传列表里可以点击路径直接修改。
3. **合并后才会生效**：提交 → 审核通过 → 合并，之后游戏内才会出现你的关卡/道具。
4. **安全与版权**（必须遵守）：
   - 只使用本文档公开的接口，**不得向 AI 或任何人索要/复制游戏源码**；
   - 不得制作破坏游戏平衡、跳过旗杆直接通关、或修改玩家物理/操作的内容；
   - 脚本在平台沙箱中运行，`eval`、`new Function`、`window`、`document`、`fetch`、`localStorage` 等危险 API 一律禁止；
   - 违反以上约定的提交会被拒绝。

## 4. 游戏方开放的接口

### 4.1 关卡数据格式（方案 A · 零代码，推荐）

关卡就是一个 JSON 对象，核心字段是一个 **15 行字符网格** `layout`，每一行用单个字符表示一个格子，宽度（列数）= 关卡宽度。

**字符对照表**：

| 字符 | 含义 | 字符 | 含义 |
|---|---|---|---|
| ` `（空格） | 空 | `[` | 管道身（左） |
| `#` | 地面 | `]` | 管道身（右） |
| `B` | 砖块 | `C` / `o` | 金币 |
| `?` | 问号金币块（顶出金币） | `M` | 蘑菇块 |
| `U` | 已用块（顶过的问号块） | `X` | 硬块（可撞碎） |
| `(` | 管道（左缘） | `F` | 旗杆 |
| `)` | 管道（右缘） | | |

**关卡字段表**：

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `id` | ✅ | string | 关卡唯一标识（如 `lvl2`） |
| `title` | ✅ | string | 关卡标题（会显示在游戏内下拉菜单） |
| `layout` | 二选一 | string / string[] / number[][] | 15 行字符网格，或等价的二维数字数组 |
| `script` | 二选一 | string | 脚本文件的相对路径（见 4.2，与 `layout` 二选一） |
| `cols` | 否 | number | 列数；缺省按 `layout` 最长一行，建议 ≥ 40 |
| `enemyCols` | 否 | number[] | 敌人（板栗仔）出生的列号数组 |
| `flag` | 否 | boolean | 默认 `true`，在关卡末尾自动放置旗杆 |
| `flagCol` / `castleCol` | 否 | number | 自定义旗杆/城堡列号（不填则自动） |

**硬性规则**：
- **行数固定 15 行**（游戏物理与出生点依赖）；不足补空、超出截断
- 每行长度相同（= 列数）；建议在底部留 1~2 行 `#` 地面
- 管道需要上下成对（`(` + `[` 构成左缘，`)` + `]` 构成右缘）
- 出生点在左侧，敌人不要放在出生点位置

**示例**（15 行的简化示意，实际请填满 15 行）：

```json
{
  "id": "lvl2",
  "title": "第二关：砖间历险",
  "cols": 50,
  "enemyCols": [18, 32],
  "layout": "                                                            ##...........##"
}
```

> 小技巧：把任务要求描述给 AI，让它按上面的字符对照表生成 15 行等宽网格，是最快的「零代码做关」方式（模板见第 5 节）。

### 4.2 脚本构建关卡（方案 B · 进阶，需少量代码）

当「纯网格表达不了」时（比如需要程序化生成），可以提交一个 `.js` 文件作为 `script`，游戏会用沙箱方式加载它。

脚本必须暴露固定接口：

```js
window.MarioLevel = {
  build: function (api) { /* 用 api 画关卡 */ }
};
```

`api` 对象提供以下方法（这就是游戏方开放的全部构建能力）：

| 方法 | 参数 | 说明 |
|---|---|---|
| `setT(col, row, value)` | 列、行、瓦片编号 | 在指定格子放一个瓦片 |
| `pipe(col, topRow)` | 列、管道顶行 | 画一个管道 |
| `stairUp(col, height)` | 列、高度 | 画一段上升阶梯 |
| `stairDown(col, height)` | 列、高度 | 画一段下降阶梯 |
| `setFlag(col)` | 列号 | 设置旗杆位置 |
| `setEnemies(cols)` | 列号数组 | 设置敌人出生列 |
| `grid` | — | 15×列 的二维数组引用，可直接 `grid[r][c] = 数值` 画瓦片 |
| `T / ROWS / COLS` | — | 常量：瓦片尺寸 / 行数(15) / 列数 |

示例（来自游戏内置的演示脚本，`level2.js`）：

```js
window.MarioLevel = { build(api){
  api.setT(8,9,3); api.pipe(22,11);
  api.stairUp(64,4); api.stairDown(116,6);
  api.setFlag(138); api.setEnemies([15,28,47]);
} };
```

### 4.3 道具创作（`items` slot）

道具是一个 JSON 对象，合并后玩家可在游戏内领取并在 PROPS 道具栏使用。完整规则见游戏目录下的《supermario-powerup — 超级玛丽道具创作 SOP》，这里摘录关键信息：

**可用预设效果**：

| 效果名 | 说明 |
|---|---|
| `add_score` | 加分，`params.bonus` 5~50 |
| `add_life` | 加一条命 |
| `become_big` | 变大 |
| `invincible` | 无敌，`params.duration` 60~300 帧 |
| `add_time` | 加时间，`params.seconds` 10~60 |
| `clear_enemies` | 清屏敌人 |

**基础示例**：

```json
{
  "name": "金币袋",
  "effect": "add_score",
  "params": { "bonus": 20 },
  "description": "立即获得 20 分",
  "icon": "💰"
}
```

进阶支持 `effectCode`（自定义效果函数，≤4000 字符，沙箱运行）与 `effectScript`（效果组合），具体见 SOP 文档。

## 6. 提交格式与步骤

在任务详情页的「提交」表单中填写：

- **data**：你的关卡对象（或关卡数组）；纯文件补丁时留空 `{}` 即可
- **assets**：需要上传的文件（脚本关卡传 `.js`，纯文件补丁传被补的文件）
- **entryPoint**：仅当你提交完整 HTML 页面时填写（一般关卡任务不用）

**提交前自检**：
- [ ] data 包含 `id`、`title`，`layout` 或 `script` 至少一个
- [ ] `layout` 正好 15 行、每行等宽、底部有地面、字符全部来自对照表
- [ ] 脚本（如有）暴露 `window.MarioLevel.build(api)`，只使用 4.2 的 api 方法
- [ ] 道具（如有）的数值在约束范围内，没有危险代码
- [ ] assets 的 path 是游戏内相对路径

## 7. 常见问题

**Q：提交后游戏里没有出现我的关卡？**
先确认任务状态是「已合并」；然后强刷页面（`Ctrl+Shift+R`）清浏览器缓存；仍没有则在游戏标题界面的「关卡」下拉里切换试试。

**Q：报「data 缺少必需字段」？**
data 里要包含 `id` 和 `title`（或按任务要求的字段）。如果是纯文件补丁，把 data 留空 `{}` 并确保上传了文件即可。

**Q：报「文件类型不允许」？**
确认文件后缀在任务允许列表内（关卡数据 `.json`、脚本 `.js`、贴图 `.png` 等）。若怀疑是旧校验缓存，联系平台刷新后重试。

**Q：我完全不会写代码，能做吗？**
可以。只做「关卡创作」或「纯文件补丁」就是纯填空/传文件；脚本关卡和自定义道具属于进阶玩法，可以完全跳过。
