# ADR-003: 单体架构（当前阶段）

**状态**: 已接受  
**日期**: 2025-06-07

## 上下文

AllinONE Gaming Platform 目前处于 MVP 阶段，团队规模小、功能范围有限。需要决定是采用微服务还是单体架构。

## 决策

采用 **模块化单体架构**：

- `server.js`：Express 应用入口（Sprint 4 后已精简至 ~290 行）
- 路由模块化：`src/server/routes/` 独立路由文件
- 服务层：`src/services/` 业务逻辑
- Skill 引擎：插件化扩展点

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 微服务 | 独立部署、技术异构 | 运维复杂、网络延迟、不适合 MVP | ❌ |
| 纯前端 SPA | 简单 | 需后端 API、数据安全 | ❌ |
| 模块化单体 | 部署简单、开发快、可逐步拆分 | 单点故障 | ✅ |

## 影响

- 部署为单个 CloudRun 服务（CPU 0.5/内存 1GB）
- 当用户量增长时可拆分：API 服务 + 静态资源分离
- 已为未来拆分做好准备（路由模块化、服务分层清晰）
